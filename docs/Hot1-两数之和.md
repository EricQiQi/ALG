# 算法笔记：两数之和（力扣 1 题）

## 题目描述
给定一个整数数组 `nums` 和一个目标值 `target`，在数组中找出**和为 target 的两个整数**，返回它们的**数组下标**。假设每种输入只有一个答案，且同一个元素不能使用两次。

```
输入: nums = [2,7,11,15], target = 9
输出: [0,1]（或 [1,0]，顺序不限）
解释: nums[0] + nums[1] = 2 + 7 = 9
```

---

## 核心思想

> **一遍哈希：边遍历边问"我的另一半来过没有"。**

暴力做法是两层循环枚举所有数对（$O(n^2)$）。用 HashMap 可以降到 $O(n)$：

- 遍历到 `nums[i]` 时，先算出它的**互补数** `complement = target - nums[i]`；
- **查** map 里有没有这个互补数——有，说明之前来过，配对成功；
- 没有，就把**当前值和下标存进 map**，等后面的人来匹配我。

```
nums = [2, 7, 11, 15], target = 9

i=0, nums[0]=2, 找 9-2=7 → map 里没有 → 存 {2:0}
i=1, nums[1]=7, 找 9-7=2 → map 里有 2（下标0）→ 命中！返回 [1, 0]
```

---

## 代码实现 (Java)

```java
public static int[] twoSum(int[] nums, int target) {
    if (nums == null || nums.length == 0) return new int[2];

    int[] res = new int[2];
    Map<Integer, Integer> map = new HashMap<>();  // key=数值, value=下标
    for (int i = 0; i < nums.length; i++) {
        if (map.containsKey(target - nums[i])) {  // 先查：另一半来过吗？
            res[0] = i;                            // 当前下标
            res[1] = map.get(target - nums[i]);    // 互补数的下标
        } else {
            map.put(nums[i], i);                   // 后存：把自己登记进账本
        }
    }
    return res;
}
```

> map 的 **key 是数值、value 是下标**——因为题目要返回的是下标，而查找时是按"数值"找"另一半"。

---

## ❗关键易错点

**1. 必须"先查后存"，不能"先存后查"**

这是本题最容易翻车的细节，和 [560 和为K的子数组](Hot560-和为k的子数组.md) 的"先查后记"是**同一个道理**：

- 若先把 `nums[i]` 存进 map 再查，当 `target = 2 × nums[i]` 时（如 target=6、nums[i]=3），会**查到自己**，等于同一个元素用了两次，违反题意。
- **先查**：查的时候当前元素还没进 map，天然避免了"自己配自己"。

**2. 用 `else` 存，找到答案后不覆盖**

命中后走的是 `if` 分支（记录结果），不会再执行 `put`。保证 map 里存的是每个值**第一次出现**的下标。

---

## 复杂度分析

* **时间复杂度**：$O(n)$。只遍历一趟，HashMap 的查/存都是 $O(1)$。
* **空间复杂度**：$O(n)$。最坏情况 map 存下几乎所有元素。

## 💡 记忆口诀

> **一边遍历一边查，target 减我找另一半；查到了就配对返回，没查到就把自己存下。切记先查后存，免得自己配自己。**
