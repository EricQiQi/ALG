# 递归

> 递归 = 拆问题 + 拼结果。前半篇讲心法和代码骨架，后半篇把做过的题一题一题按三问填表。

## 一、递归的本质

```
递归(大问题) {
    1. 终止条件 → 小到能直接回答
    2. 拆 → 把大问题拆成更小的同类问题（调用自己）
    3. 拼 → 用小问题的答案拼出大问题的答案
}
```

## 二、递归三板斧

| 要素 | 说明 | 易错点 |
| :--- | :--- | :--- |
| **终止条件** | 递归到什么时候停 | 漏写 → 栈溢出 |
| **拆解** | 调用自身，参数更小 | 参数没变小 → 无限递归 |
| **拼接** | 用子问题的返回值构造当前层的答案 | 忘了用返回值 / 返回值用错 |

## 三、三问是什么

写递归不用在脑子里把整个递归栈展开，只问自己三件事：

| 问题 | 要回答什么 | 想不清楚的后果 |
| :--- | :--- | :--- |
| **① 什么时候停** | 小到什么程度就不用再往下拆了，直接给答案 | 漏写或写错 → 栈溢出 / 答案差一层 |
| **② 这一层做什么** | 不算递归调用，只看眼前这一个节点（或这一对数）该怎么操作 | 把"整条链怎么翻"塞进脑子 → 越写越乱 |
| **③ 返回值怎么用** | 子问题交回来的东西，接在哪、和谁拼 | 忘了用返回值 / 用错 → 链断掉、答案丢失 |

> 心法：**相信子问题一定被解决**。你只需要对"当前这一层"负责，剩下的交给下一层。

## 四、链表递归：相信后面的兄弟

| 题目 | ① 什么时候停 | ② 这一层做什么 | ③ 返回值怎么用 |
| :--- | :--- | :--- | :--- |
| [206 反转链表](Hot206-反转链表.md) | `head == null \|\| head.next == null` | 让 `head.next.next = head`，再把 `head.next = null` 收尾 | 递归返回的是新头，本层也原样往上传 |
| [24 两两交换](Hot24-两两交换链表中的节点.md) | `head == null \|\| head.next == null` | 第 2 个 `newHead` 变新头，第 1 个 `head` 挂到后面 | `swapPairs(newHead.next)` 的结果接到 `head.next`，返回 `newHead` |
| [25 K 个一组翻转](Hot25-K个一组翻转链表.md) | 先数长度，不够 k 个就不再翻 | 把这一组 k 个节点整体翻转 180° | 把递归结果接在翻转后的尾巴上，返回翻转后的新头 |
| [21 合并两个有序链表](Hot21-合并两个有序链表.md) | 任意一条为空，直接返回另一条 | 比较两个头，挑小的那个当结果头 | 小头的 `next` 接 `merge(剩下两段)`，返回小头 |
| [148 链表排序](Hot148-链表排序.md) | `head == null \|\| head.next == null` | 快慢指针找中点，把链表断成两半 | 两半各自排好后 `merge`，返回合并后的头 |
| [23 合并 K 个升序链表](Hot23-合并K个升序链表.md) | 区间只剩一个链表，直接返回它 | 从中间把 k 条链表劈成两组 | `merge(左组结果, 右组结果)`，返回合并后的头 |
| [138 复制带随机指针的链表](Hot138-复制带随机指针的链表.md) | `node == null` | `new` 一个克隆节点，先塞进 HashMap 占坑 | 递归拿 `next` / `random` 时用 map 查克隆节点，返回当前克隆节点 |

**一句话总结**：链表递归的"当前层"永远是**一两个节点之间的指针关系**，返回值永远是**处理好的那一段的新头**。

## 五、二叉树递归：左边一次、右边一次、再合起来

| 题目 | ① 什么时候停 | ② 这一层做什么 | ③ 返回值怎么用 |
| :--- | :--- | :--- | :--- |
| [94 中序遍历](Hot94-二叉树的中序遍历.md) | `node == null` | 只负责"访问自己"这一步（中序就夹在两次递归之间） | 左右递归的结果直接写进同一个 list，本层不返回东西 |
| [104 最大深度](Hot104-二叉树的最大深度.md) | `node == null → 0` | 不做事，只要左右两边的答案 | `1 + max(左, 右)` 交给上一层 |
| [226 翻转二叉树](Hot226-翻转二叉树.md) | `node == null` | 交换自己的左右孩子 | 递归把手里的左右子树整棵翻好，返回本节点 |
| [101 对称二叉树](Hot101-对称二叉树.md) | 两个都空 → true；一个空 → false | 比较两个节点的值是否相等 | 继续比 `left.left vs right.right` 和 `left.right vs right.left`，两个都 true 才 true |
| [543 二叉树的直径](Hot543-二叉树的直径.md) | `node == null → 0` | 拿自己当拐点，`ans = max(ans, 左深度 + 右深度)` | 只能返回 `1 + max(左, 右)`——往上走只能挑一边 |
| [98 验证二叉搜索树](Hot98-验证二叉搜索树.md) | `node == null → true` | 检查自己是否落在 `(min, max)` 区间里 | 往左递归收紧 max、往右递归收紧 min，两边都 true 才 true |
| [108 有序数组转 BST](Hot108-有序数组转二叉搜索树.md) | `left > right → null` | 取中点当根 | 左右两半递归出来的子树挂到根的左右，返回根 |
| [105 前序+中序构造二叉树](Hot105-从前序与中序遍历序列构造二叉树.md) | 区间为空 → null | 前序取第一个当根，中序查根的位置分出左右两部分 | 递归建好的左右子树接到根上，返回根 |
| [114 展开为链表](Hot114-二叉树展开为链表.md) | `node == null` | 把展开后的左链挂到右边，原右子树接到左链的尾巴上 | 递归只管把左右两边各自"拉直"，本层返回 void |
| [236 最近公共祖先](Hot236-二叉树的最近公共祖先.md) | `node == null` 或 `node == p/q` | 自己先表态：我就是 p/q 就把自己交上去 | 左右两边都有结果 → 自己就是答案；只有一边有 → 把那边传上去 |
| [124 最大路径和](Hot124-二叉树中的最大路径和.md) | `node == null → 0` | 拿自己当拐点，`ans = max(ans, 左 + 自己 + 右)` | 往上只能走一边：返回 `自己 + max(左, 右, 0)`，负数直接不要 |
| [437 路径总和 III](Hot437-路径总和III.md) | `node == null` | 一边把当前节点当起点往下搜，一边在 map 里记前缀和 | 前缀和查账后要**回溯删掉自己**，否则会污染兄弟子树 |
| [230 第 K 小](Hot230-二叉搜索树中第K小的元素.md) | `node == null` | 中序走一步就数一个数 | 数到第 k 个就停手，答案存在全局变量里带出去 |
| [199 右视图](Hot199-二叉树的右视图.md) | `node == null` | 先走右子树，再走左子树 | 第一次抵达某个深度时把节点记下来，深度超过 list 长度才记 |

**一句话总结**：树的"当前层"永远只关心**自己的值 + 左右两个孩子交回来的东西**；如果答案可能"穿过自己"，就顺手更新一个全局变量。

## 六、回溯递归：多一步"撤销"

回溯就是带撤销的递归，三问的答案都短：

| 题目 | ① 什么时候停 | ② 这一层做什么 | ③ 返回值怎么用 |
| :--- | :--- | :--- | :--- |
| [46 全排列](Hot46-全排列.md) | 路径长度等于 n | 把候选池里一个数换到当前位上 | 不返回，递归回来后把换过的位置换回去 |
| [78 子集](Hot78-子集.md) | 每个节点一进门就收割（含空集） | 从 `start` 往后挑一个数 | 不返回，回来后把刚加的数删掉 |
| [39 组合总和](Hot39-组合总和.md) | `target == 0` 收割；`target < 0` 剪枝 | 挑一个数，`target` 减去它 | 不返回，回来后把数删掉、`target` 加回来 |
| [22 括号生成](Hot22-括号生成.md) | 长度到 2n | 左括号看余量、右括号看欠账，能放就放 | 不返回，回来后删掉刚放的括号 |
| [51 N 皇后](Hot51-N皇后.md) | 放满 n 行 | 在当前行挑一列，检查三个方向有没有冲突 | 不返回，回来后把这一格擦掉换下一列 |
| [79 单词搜索](Hot79-单词搜索.md) | 匹配完最后一个字母 → true | 站在格子上试四个方向 | `true` 就往上传，`false` 就擦标记换方向 |

**一句话总结**：回溯的返回值基本没用（要么 void，要么传个 boolean），真正的主角是**递归前后那对"加上/撤销"**。

## 七、四类题的代码骨架

上表的题全部能套进四个骨架，写题时直接往里填三问的答案。

### 7.1 树：左边一次、右边一次、再合起来

```java
int dfs(TreeNode node) {
    if (node == null) return 基础值;     // 停
    int left  = dfs(node.left);         // 拆
    int right = dfs(node.right);        // 拆
    return 用 left, right 拼出答案;     // 拼
}
```

> 答案可能"穿过自己"时，在 return 前顺手更新全局变量（543 直径、124 最大路径和都是这个套路）。

### 7.2 链表：只管一两个节点的指针

```java
ListNode dfs(ListNode head) {
    if (head == null || head.next == null) return head;  // 停
    ListNode rest = dfs(head.next);  // 拆：后面全交给你
    head.next.next = head;           // 拼：把自己接回尾部
    head.next = null;
    return rest;                     // 新头往上交
}
```

> 这是 206 的模板。24/25/21 只是把「拼」那两行换成两两交换、分组翻转、比大小合并。

### 7.3 分治：切两半各自解决再合并

```java
T f(问题) {
    if (问题足够小) return 直接解决;   // 停
    int mid = 分界点;                  // 分
    T left = f(左半);                  // 治
    T right = f(右半);                 // 治
    return merge(left, right);         // 合
}
```

> 148 找中点断链、23 从中间劈 k 条、108 取中点当根、105 前序定根拆分，全部是这一套。

### 7.4 递归 + 记忆化：把算过的存起来

```java
Map<Node, Node> map = new HashMap<>();
Node dfs(Node node) {
    if (node == null) return null;              // 停
    if (map.containsKey(node)) return map.get(node);  // 算过就直接拿
    Node copy = new Node(node.val);
    map.put(node, copy);                        // 先占坑，再递归
    copy.next = dfs(node.next);
    copy.random = dfs(node.random);
    return copy;
}
```

> 138 的解法。先 `put` 再递归是关键，少了 `containsKey` 那行，遇到环形结构会无限递归。

## 八、四类题怎么一眼认出来

| 特征 | 用哪套三问 | 代表题 |
| :--- | :--- | :--- |
| 结构本身就是链表/树，天然可分 | 当前层只管一两个节点，返回值是新头 | 206、24、绝大部分树题 |
| 大问题能切成两半，各自独立 | 找中点/分界点 → 两边递归 → 合并结果 | 148、23、108、105 |
| 要暴力枚举所有可能 | 终止条件 = 长度/目标到了 → 尝试 → **撤销** | 46、78、39、22、51、79 |
| 答案可能"穿过当前节点" | 递归返回值算一边，全局变量记完整答案 | 543、124、437、236 |

## 九、递归 vs 迭代（什么时候别用递归）

| 题目 | 递归写法 | 迭代写法 | 备注 |
| :--- | :--- | :--- | :--- |
| 206 反转链表 | 3 行核心代码 | prev/curr/next 三个指针 | 递归更简洁，但深链表会爆栈 |
| 94 二叉树遍历 | 递归三行 | 需要栈模拟 | 递归更直观 |
| 102 层序遍历 | 不自然 | BFS 队列 | **迭代更合适** |
| 148 链表排序 | 自顶向下归并 | 自底向上归并可做到 O(1) 空间 | 各有优势 |

> 递归的隐性成本是 O(n) 的调用栈。树 DFS 用递归天然合适，BFS 用队列更自然，链表很长时优先迭代。

## 十、速记口诀

```
递归三问一张表：何时停、做什么、返回值往哪搁。
链表只看指针线，树看左右再合并；
回溯多写一行撤，全局变量记答案。
```
