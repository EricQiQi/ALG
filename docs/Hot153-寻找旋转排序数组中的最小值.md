# LeetCode 153. 寻找旋转排序数组中的最小值

对应源码：[Hot153_findMin.java](../src/s11_binarySearch/Hot153_findMin.java)

## 题目描述

一个原本**升序、无重复元素**的数组 `nums`，在某个下标处被**旋转**了 1 到 n 次（例如 `[0,1,2,4,5,6,7]` 旋转后可能变成 `[4,5,6,7,0,1,2]`）。

请找出并返回数组中的**最小元素**。

要求时间复杂度为 `O(log n)` —— 即必须用二分查找。

例：

```
nums = [3,4,5,1,2]       → 1
nums = [4,5,6,7,0,1,2]   → 0
nums = [11,13,15,17]     → 11   （旋转 n 次相当于没转，仍是最左元素）
```

## 💡 大白话解析

旋转数组的关键性质：**从任意位置 `mid` 切开，左右两半里必有一半是完全有序的**，而最小值（旋转点）就藏在「乱序的那一半」里，或者说在有序半区的**紧右边**。两种方法都基于这一点。

### 方法一：记录有序半区的最小值（ans 打擂台）

沿用 Hot33 的思路，每轮先判断哪半有序，把**有序半区的最小值**（就是它的左端点）拿去和 `ans` 打擂台，然后**丢弃这个有序半区**、去另一半继续找：

- `nums[left] <= nums[mid]`：左半区 `[left, mid]` 有序，它的最小值是 `nums[left]`，用 `ans = min(ans, nums[left])` 记账，然后 `left = mid+1` 去右半区；
- 否则右半区 `[mid, right]` 有序，说明旋转点（最小值）在左半区，此时 `nums[mid]` 是右半区最小值也是候选，用 `ans = min(ans, nums[mid])` 记账，然后 `right = mid-1` 去左半区。

`ans` 初始化为 `nums[0]`，循环用闭区间 `left <= right`，扫完所有有序半区后 `ans` 即全局最小。

### 方法二：直接收缩到最小值所在半区（更简洁）

不额外记账，直接比较 `nums[mid]` 和**右端点** `nums[right]`，判断最小值落在哪半：

- `nums[mid] > nums[right]`：说明 mid 在**前半段大值区**，最小值一定在 mid **右边**，`left = mid+1`；
- `nums[mid] <= nums[right]`：说明 mid 已在**后半段（含最小值）**，最小值在 `[left, mid]`，`right = mid`（**保留 mid**，因为它可能就是答案）。

循环条件用 `left < right`（区间收缩到只剩一个元素时退出），最终 `left == right` 指向的就是最小值。

```
方法二：nums = [4,5,6,7,0,1,2]

left=0 right=6 mid=3 → nums[3]=7 > nums[6]=2 → 最小值在右边 → left=4
left=4 right=6 mid=5 → nums[5]=1 <= nums[6]=2 → right=5
left=4 right=5 mid=4 → nums[4]=0 <= nums[5]=1 → right=4
left=4 == right=4，退出 → 返回 nums[4]=0
```

**为什么方法二比 `nums[right]` 而不比 `nums[left]`？** 比 `nums[left]` 无法区分「整体没旋转」和「旋转点恰好在中间」两种情况（都可能 `nums[mid] >= nums[left]`），会误判；比右端点则能干净地判断 mid 落在大值区还是小值区。

## 💻 Java 代码实现

### 方法一：ans 记录有序半区最小值

```java
public int findMin_1(int[] nums) {
    int left = 0, right = nums.length - 1;
    int ans = nums[0];                             // 先拿最左元素兜底
    while (left <= right) {                        // 闭区间，扫完为止
        int mid = left + (right - left) / 2;       // 防溢出
        if (nums[left] <= nums[mid]) {             // 左半区 [left, mid] 有序
            ans = Math.min(nums[left], ans);       // 有序半区最小值 = 左端点，记账
            left = mid + 1;                        // 丢弃有序左半，去右边找旋转点
        } else {                                   // 右半区 [mid, right] 有序
            ans = Math.min(nums[mid], ans);        // nums[mid] 是候选最小值，记账
            right = mid - 1;                       // 旋转点在左半，去左边找
        }
    }
    return ans;
}
```

### 方法二：收缩到最小值所在半区

```java
public int findMin_2(int[] nums) {
    int left = 0, right = nums.length - 1;
    while (left < right) {                         // 收缩到只剩一个元素时退出
        int mid = left + (right - left) / 2;       // 防溢出
        if (nums[mid] > nums[right]) {             // mid 在大值区，最小值在右边
            left = mid + 1;                        // mid 本身不可能是最小值，可跳过
        } else {                                   // mid 在小值区（含最小值）
            right = mid;                           // mid 可能就是最小值，保留它
        }
    }
    return nums[left];                             // left == right，即最小值
}
```

## 复杂度分析

| 方法 | 时间 | 空间 | 说明 |
| :--- | :---: | :---: | :--- |
| 方法一（ans 打擂台） | O(log n) | O(1) | 闭区间 `left<=right`，每轮记录有序半区最小值后丢弃 |
| 方法二（收缩到最小值） | O(log n) | O(1) | 开区间 `left<right`，比右端点直接定位最小值半区，代码更短 |

两者复杂度同阶，方法二无需额外变量、逻辑更聚焦，是本题首选写法。

## ⚠️ 易错点

1. **方法二 `right = mid` 不能写成 `mid-1`**：`nums[mid] <= nums[right]` 时 mid 本身可能就是最小值，写成 `mid-1` 会把它跳过导致答案错误。相应地 `left = mid+1` 可以，因为 `nums[mid] > nums[right]` 时 mid 一定不是最小值。
2. **方法二循环条件必须是 `left < right`**：因为 `right = mid` 保留 mid，若用 `left <= right` 且区间只剩一个元素时 `right = mid` 不再变化，会**死循环**。
3. **方法二比较对象是 `nums[right]` 而非 `nums[left]`**：比左端点无法区分「未旋转」和「旋转点在中间」，会误判收缩方向。
4. **方法一 `ans` 初值**：设为 `nums[0]` 可覆盖「数组完全没旋转」的情况（此时最小值就是 `nums[0]`）。
5. **方法一判断有序用 `<=`**：与 Hot33 同理，`nums[left] <= nums[mid]` 才能正确处理 `left == mid`（区间只剩一个元素）的情况。

## 🆚 两种方法对比

| | 方法一（ans 打擂台） | 方法二（收缩到最小值） |
| :--- | :--- | :--- |
| 循环条件 | `left <= right`（闭区间） | `left < right`（剩一个即停） |
| 比较对象 | `nums[left]` vs `nums[mid]`（判哪半有序） | `nums[mid]` vs `nums[right]`（判最小值在哪半） |
| 额外变量 | 需要 `ans` 记录候选最小值 | 不需要，最后 `nums[left]` 即答案 |
| 收缩方式 | 记账后丢弃有序半区 | 直接保留含最小值的半区（`right=mid`） |
| 推荐度 | 思路承接 Hot33，好理解 | 更简洁，首选 |

## 🧠 记忆口诀

> **最小值在「乱序的那半」。方法一：判断哪半有序，记下有序半区左端点当候选，丢弃有序半区去另一边。方法二：比右端点——`nums[mid] > nums[right]` 去右边（`left=mid+1`），否则 `right=mid` 保留 mid；循环用 `left<right` 防死循环。**

## 📌 备注

该题属于**二分查找**题型，源文件归入 `s11_binarySearch` 包，与 [搜索旋转排序数组](Hot33-搜索旋转排序数组.md) 是「旋转数组二分」的一对姊妹题：Hot33 找**指定 target**、本题找**最小值（旋转点）**，核心都是「mid 切开必有一半有序」。若数组**含重复元素**（LeetCode 154），当 `nums[mid] == nums[right]` 时无法判断，只能 `right--` 逐步收缩，最坏退化到 `O(n)`。
