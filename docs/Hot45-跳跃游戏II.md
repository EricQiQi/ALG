# 算法笔记：跳跃游戏 II（力扣 45 题）

## 题目描述
给你一个非负整数数组 `nums` ，你最初位于数组的 **第一个下标** 。

数组中的每个元素代表你在该位置可以跳跃的 **最大长度** 。

你的目标是使用 **最少的跳跃次数** 到达数组的 **最后一个下标** 。

> 📌 关键理解：与[跳跃游戏 I](Hot55-跳跃游戏.md)相同，`nums[i]` 是「**最多**能跳这么远」，即在位置 `i` 你可以跳 `1 ~ nums[i]` 之间的**任意**步数，**不是必须**恰好跳 `nums[i]` 步。题目保证一定可以到达终点。

---

## 解法：贪心算法（按层扩张 / 双边界）

### 1. 核心思想
上一题只问“能否到达”，本题多问一句“**最少跳几次**”。把每一次跳跃能覆盖的范围看作 BFS 里的**一层**：在这一层内扫描所有可达位置，探出**下一层能到达的最远下标**；当遍历到本层右边界时，说明本层探索完毕，必须再跳一次，并把右边界推进到下一层的最远处。
* `end`：当前这一跳（本层）能覆盖的**右边界**，遍历下标 `i` 到达它时本层结束。
* `maxPosition`：在本层内所有位置出发，下一跳能到达的**最远下标**，即下一层的右边界。
* `count`：跳跃次数（层数）。每当 `i == end` 说明本层走完，`count++` 并把 `end` 推进到 `maxPosition`。

> 贪心点：在“当前这一步能覆盖的区间”内，不急着决定落点，而是把区间内所有点的可达范围都探完，取**最远**的那个作为下一步的边界。这保证每一次跳跃都尽可能覆盖更远，从而总次数最少。

### 2. 代码实现 (Java)
循环只遍历到 `n - 2`（不处理最后一个下标），因为一旦边界覆盖终点就无需再“多跳一步”。

```java
class Solution {
    public int jump(int[] nums) {
        int n = nums.length;
        if (n == 1) return 0;

        int count = 0;        // 跳跃次数
        int maxPosition = 0;  // 下一跳能到达的最远下标
        int end = 0;          // 当前这一跳覆盖的右边界

        for (int i = 0; i < n - 1; i++) {
            // 在本层内不断扩张下一层的最远边界
            maxPosition = Math.max(maxPosition, i + nums[i]);

            // 走到本层右边界：本层探索完毕，必须再跳一次
            if (i == end) {
                count++;
                end = maxPosition; // 右边界推进到下一层最远处
            }
        }
        return count;
    }
}
```

### 3. 复杂度分析
* **时间复杂度**：$O(n)$。每个下标只被访问一次。
* **空间复杂度**：$O(1)$。只使用了 `count`、`maxPosition`、`end` 三个额外变量。

### 4. 遍历过程图解
以 `nums = [2,3,1,1,4]`（n=5，终点下标 4）为例，循环跑 `i = 0..3`：

```text
i   nums[i]  maxPosition=max(mp, i+nums[i])   i == end?   count   end
0      2            max(0, 0+2) = 2           是(0==0)      1      2
1      3            max(2, 1+3) = 4           否            1      2
2      1            max(4, 2+1) = 4           是(2==2)      2      4
3      1            max(4, 3+1) = 4           否            2      4
```

> 第 1 跳覆盖 `[0, 2]`（i=0 时 end 从 0 推进到 2）；第 2 跳在 i=2 处把 end 推进到 4，覆盖终点，共 2 次。

配合分层视角理解“一次跳跃 = 一层”：

```text
第 0 层(end=0):   [0]                 ← 起点
                  ↓ 本层能到 1、2，最远 2
第 1 层(end=2):   [1, 2]              ← 第 1 跳覆盖，count=1
                  ↓ 从 1、2 出发最远到 4
第 2 层(end=4):   [3, 4]              ← 第 2 跳覆盖终点，count=2
```

### 5. 概念澄清：`end` 与 `maxPosition` 的分工
`end` 和 `maxPosition` 都是“边界”，但含义不同，混淆了就会把层数算错：

| | `end` | `maxPosition` |
| :--- | :--- | :--- |
| 含义 | **本层**（当前这一跳）的右边界 | **下一层**能到达的最远下标 |
| 何时更新 | `i == end` 时赋值为 `maxPosition` | 每到一个位置就 `max` 扩张 |
| 作用 | 触发 `count++` 的“哨兵” | 决定下一层的 `end` |

**为什么 `i == end` 才 `count++`：** `end` 是本层右边界，遍历指针 `i` 扫到它，意味着本层内所有位置都已探完、下一层最远处 `maxPosition` 已确定，此时才需要“真正落一次脚”再跳一次。若改成 `maxPosition` 一有更新就 `count++`，会在同一层内重复计数。

---

## 💡 总结
跳跃游戏 II 把“最少跳几次”转化为**分层贪心 / BFS 层序**：每层尽力探出下一层最远边界，走到层边界才跳一次。它与[跳跃游戏 I](Hot55-跳跃游戏.md)同源——都维护“可达最远下标”，区别只在于本题多了 `end` 这一层边界来计数。

| 特性 | 说明 |
| :--- | :--- |
| **思维出发点** | 每一跳覆盖一层，层内尽力扩张下一层最远边界。 |
| **代码表现** | `maxPosition` 持续 `max` 扩张；`i == end` 时 `count++` 且 `end = maxPosition`。 |
| **时间 / 空间** | $O(n)$ / $O(1)$，一次遍历、三变量。 |

> ⚠️ 对比记忆：**跳跃游戏 I 只维护一个边界 `maxStep` 判可达**（$O(n)$ 判“能不能到”）；**跳跃游戏 II 多维护一个层边界 `end`**（$O(n)$ 算“最少几步”）。两题循环都到 `n - 2` 为止，避免在终点处多算一次。
