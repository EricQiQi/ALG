# LeetCode 394. 字符串解码

对应源码：[Hot394_decodeString.java](../src/s12_stack/Hot394_decodeString.java)

## 题目描述

给定一个经过编码的字符串，返回它解码后的字符串。编码规则为 `k[encoded_string]`，表示方括号内部的 `encoded_string` 正好重复 `k` 次。`k` 保证为正整数，且输入中除了重复次数没有其他数字。

```
"3[a]2[bc]"     → "aaabcbc"
"3[a2[c]]"      → "accaccacc"
"2[abc]3[cd]ef" → "abcabccdcdcdef"
```

## 💡 大白话解析

难点只有一个：**括号可以嵌套**。`3[a2[c]]` 里，内层的 `2[c]` 必须先算完，外层的 `3[...]` 才知道自己要重复什么。

这就是「**最近打开的括号最先闭合**」——后进先出，天生用栈。

关键设计：**遇到 `[` 时不是简单地"开始记录"，而是把当前现场整体存进栈里，然后清空工作区**。因为此刻你手里有两样东西必须记住：

| 存什么 | 存到哪个栈 | 为什么必须存 |
| :--- | :--- | :--- |
| 重复次数 `num` | `countStack` | `]` 时要靠它决定重复几遍 |
| 进括号**之前**已拼好的前缀 `currStr` | `stringStack` | 括号外可能已经有内容了，如 `2[abc]3[cd]ef` 处理第二段时，前缀是 `"abcabc"` |

于是整个算法就变成一对动作：

- **`[` = 存现场**：`(次数, 前缀)` 双双压栈 → 清空 `currStr` 和 `num` → 进括号内部干活
- **`]` = 恢复现场**：弹出前缀和次数 → `currStr = 前缀 + 本层内容 × 次数`

两种实现的区别只在于**现场存在哪**：方法一存在两个自己开的栈里，方法二存在系统调用栈的局部变量里。

## 方法一：双栈（显式存现场）

### 图解

以 `"3[a2[c]]"` 为例（栈按 底→顶 排列）：

```
读到   currStr    countStack   stringStack   动作
 3     ""         [ ]          [ ]           num = 3
 [     ""         [ 3 ]        [ "" ]        存现场，清空工作区
 a     "a"        [ 3 ]        [ "" ]        字母直接拼
 2     "a"        [ 3 ]        [ "" ]        num = 2
 [     ""         [ 3, 2 ]     [ "", "a" ]   存现场（前缀是 "a"！），清空工作区
 c     "c"        [ 3, 2 ]     [ "", "a" ]
 ]     "acc"      [ 3 ]        [ "" ]        弹 2 和 "a" → "a" + "c"×2
 ]     "accaccacc" [ ]         [ ]           弹 3 和 ""  → "" + "acc"×3
```

**注意倒数第三行**：内层 `[` 压进字符串栈的是 `"a"`——它是内层括号**外面**、外层括号**里面**的内容。这一层前缀能不能正确保存，是双栈方案区别于"只存次数"的核心。

### 代码实现

```java
public String decodeString(String s) {
    Deque<Integer> countStack = new ArrayDeque<>();   // 待重复的次数
    Deque<String> stringStack = new ArrayDeque<>();   // 进本层括号前的前缀

    int num = 0;            // 正在累积的数字（可能多位）
    String currStr = "";    // 当前层已解析出的字符串

    for (char ch : s.toCharArray()) {
        if (Character.isDigit(ch)) {
            num = num * 10 + ch - '0';              // 多位数逐位累积
        } else if (ch == '[') {
            countStack.push(num);                   // 存现场
            stringStack.push(currStr);
            currStr = "";                           // 清空工作区
            num = 0;
        } else if (ch == ']') {
            StringBuilder temp = new StringBuilder(stringStack.pop());  // 恢复现场
            int times = countStack.pop();
            for (int i = 0; i < times; i++) {
                temp.append(currStr);               // 先前缀，再重复内容
            }
            currStr = temp.toString();
        } else {
            currStr += ch;                          // 普通字母
        }
    }
    return currStr;   // 最外层若无括号包裹，结果就留在这里
}
```

四个分支对应四类字符，**一次遍历、没有回退**。

## 方法二：递归（系统栈隐式存现场）

方法一用两个**显式栈**保存现场，递归则把这件事交给**系统调用栈**：每一层 `decodeString_2` 调用都自带一份局部的 `curr` 和 `count`，这一份就是「本层的现场」，根本不需要手写栈。

于是 `[` 和 `]` 的含义变了：

| 字符 | 双栈版 | 递归版 |
| :---: | :--- | :--- |
| `[` | 把 `(次数, 前缀)` 压栈，清空工作区 | **递归入口**：跳过 `[`，递归解析括号内部，拿到结果后重复 `count` 次接到当前层 |
| `]` | 弹栈，拼「前缀 + 本层 × 次数」 | **返回信号**：本层结束，把 `curr` 交给上一层 |

粘合剂是一个**所有递归层共享的全局指针 `i`**：每层都从 `i` 当前位置往后读，下层消费掉的字符上层不会重复读。

### 图解

以 `"3[a2[c]]"` 为例，展示递归层与指针位置：

```
s = "3[a2[c]]"
     0123456789  ← 下标

decodeString_2()            i=0 起
├─ '3' → count=3            i=1
├─ '[' → i++ 到 2，递归 ↓
│   decodeString_2()        i=2 起
│   ├─ 'a' → curr="a"       i=3
│   ├─ '2' → count=2        i=4
│   ├─ '[' → i++ 到 5，递归 ↓
│   │   decodeString_2()    i=5 起
│   │   ├─ 'c' → curr="c"   i=6
│   │   └─ ']' → i++ 到 7，break，返回 "c"
│   ├─ curr = "a" + "c"×2 = "acc"，count 清零
│   └─ ']' → i++ 到 8，break，返回 "acc"
└─ curr = "" + "acc"×3 = "accaccacc"，返回
```

**递归层数 = 括号嵌套深度**，与方法一里栈的最大高度完全对应。这就是两种写法同构的直接证据。

### 代码实现

```java
int i = 0;   // 全局读指针，所有递归层共享

public String decodeString_2(String s) {
    StringBuilder curr = new StringBuilder();   // 本层现场
    int count = 0;
    while (i < s.length()) {
        char ch = s.charAt(i);
        if (Character.isDigit(ch)) {
            count = count * 10 + ch - '0';      // 多位数逐位累积
            i++;
        } else if (ch == '[') {
            i++;                                // 先跳过 '['，否则递归一进门又看到它
            String inner = decodeString_2(s);   // 钻进去解析括号内部
            for (int i = 0; i < count; i++) curr.append(inner);
            count = 0;                          // 次数用完清零
        } else if (ch == ']') {
            i++;                                // 消费掉 ']'，让上层从下一格继续
            break;                              // 本层结束，返回给上一层
        } else {
            curr.append(ch);
            i++;
        }
    }
    return curr.toString();
}
```

### 递归版的指针契约（三个易错点）

指针 `i` 是共享的，“谁消费谁前进”必须严格遵守：

1. **`[` 分支要先 `i++` 再递归**：不跳过的话，递归一进门看到的还是 `[`，会无限递归直到栈溢出。
2. **`]` 分支要先 `i++` 再 `break`**：`break` 只结束本层循环，`i` 必须已经越过 `]`；否则上层拿到 `]` 会立即 break，后面所有字符全丢。
3. **递归返回后不要再 `i++`**：下层已经把 `]` 消费掉了，指针正好停在下一格，再动一下就跳字符。

### ⚠️ 两个现存隐患

**隐患一：`i` 是实例字段，不会自动复位。** 同一个对象第二次调用会从上次的结束位置开始，直接返回空串。实测：

```java
Hot394_decodeString r = new Hot394_decodeString();
r.decodeString_2("3[a]");   // "aaa"
r.decodeString_2("3[a]");   // ""  ← i 已停在 4，while 条件直接不成立
```

三种修法任选：调用前手动 `i = 0`；或把 `i` 改成方法内的 `int[] idx = {0}` 作为参数传递；或包一层 public 方法专门负责复位。

**隐患二：`for (int i = 0; ...)` 遮蔽了实例字段 `i`。** Java 允许局部变量遮蔽字段，所以能编译、结果也正确（循环体内用的是局部 `i`，循环结束后又回到字段 `i`）；但两个 `i` 含义完全不同，极易误改。建议把循环变量改名为 `k`。

## 复杂度分析

| 方法 | 时间 | 空间 |
| :--- | :---: | :--- |
| 双栈 | O(n) | O(n)，栈内各层前缀总长 |
| 递归 | O(n) | O(n) + O(嵌套深度) 的系统调用栈 |

n 指**解码后**字符串的长度，而非输入长度：`"10[a]"` 输入 6 个字符，输出 10 个；`"10[10[a]]"` 输入 9 个字符，输出 100 个。每个字符最终都要被拼出来一次，这是无法压缩的下界。

## 🧠 方法对比

| 方法 | 思路 | 优劣 |
| :--- | :--- | :--- |
| **双栈**（方法一） | `[` 存现场、`]` 恢复现场，一次遍历 | 无递归栈开销，所有状态都是局部的、可重复调用，**面试首选** |
| **递归**（方法二） | `[` 当递归入口、`]` 当返回信号，全局指针 `i` 串起所有层 | 代码更短、嵌套逻辑更自然；代价是共享指针难维护（三条契约）、需额外的状态复位 |
| 单栈存对象 | 把 `(次数, 前缀)` 打包成一个节点压进一个栈 | 只需一个栈，但要多定义一个类，可读性反而下降 |

双栈与递归本质相同——**递归用系统栈隐式保存现场，双栈用显式栈保存现场**。把方法一里的 `countStack`/`stringStack` 换成每层递归的 `count`/`curr` 局部变量，就得到了方法二；反过来把递归的局部变量手动压栈，就得到了方法一。

## 🧠 记忆口诀

> **双栈：`[` 存现场（次数 + 前缀），`]` 恢复现场（前缀 + 本层 × 次数）；数字要累积，存完要清空。**
>
> **递归：`[` 跳过再往下钻，`]` 跳过再往上返；指针 `i` 全局共享，谁消费谁前进。**
