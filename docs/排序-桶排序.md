# 排序算法

## 桶排序 (Bucket Sort)

### 核心思想

> **按值撒进若干个桶，桶内各自排序，再按桶号从小到大把元素收回来**

计数排序是"每个可能的值占一个格子"的极端情况；桶排序把"一个值一格"放宽成"一段区间一桶"。只要数据**分布均匀**，每个桶里就没几个元素，桶内排序几乎瞬时，整体逼近线性。

---

### 图像记忆法：分桶→桶内排→倒回

```
数据都在 [0,1)，n=7 个桶，落点 index = floor(num * n)

0.42 0.32 0.33 0.52 0.37 0.47 0.51
  ×7 →  2   2   2   3   2   3   3     ← 撒进桶

桶2: [0.42,0.32,0.33,0.37] → 桶内排序 → [0.32,0.33,0.37,0.42]
桶3: [0.52,0.47,0.51]      → 桶内排序 → [0.47,0.51,0.52]
其余桶空

按桶号 0→6 依次倒回：[0.32,0.33,0.37,0.42,0.47,0.51,0.52]
```

**关键：桶号本身就是大小顺序，所以只要"桶间按号收、桶内先排好"，整体就有序。**

---

### 一句话记住

```
乘系数定桶号撒进去，每个桶单独排序，再按桶号从小到大倒回来
```

---

### 代码结构速记

```
bucketSort(arr)                    ← 这里 arr 是 [0,1) 的 double
├── n = arr.length
├── 建 n 个空桶 buckets
├── for num in arr:
│   └── index = (int)(num * n)     ← 用值算落点，撒进对应桶
│       buckets.get(index).add(num)
├── for bucket in buckets:
│   └── Collections.sort(bucket)   ← 桶内各自排序
└── 按桶 0→n-1 顺序，把桶内元素依次写回 arr
```

---

### 关键易错点

**1. 前提：数据必须落在已知、均匀的范围（这里是 [0,1)）**

`index = (int)(num * n)` 直接把值映射成桶号。若 num 可能 ≥ 1 或为负，桶号就越界。真实数据要先**归一化**到 [0,1)：`(value - min) / (max - min)`。

**2. `num` 无限接近 1 时 `num * n` 可能等于 n → 越界**

桶下标只有 `0..n-1`。经典处理：把 `num == 1.0`（或归一化后恰好等于 1）单独塞进最后一个桶，或用 `(n-1)` 缩放。本实现假设数据严格 `< 1`。

**3. 桶的个数要适中**

桶太少 → 单个桶元素多，桶内排序拖慢；桶太多 → 空桶占空间。经验上取 `n` 个桶，均匀分布时期望每桶约 1 个，才能到 O(n)。

**4. 整体有序靠"桶号有序 + 桶内先排好"两件事**

收集阶段必须**按桶号从小到大**遍历，且每个桶**内部先排好序**，缺一不可。桶内用稳定排序（如本例 TimSort）+ 稳定收集，桶排序才是**稳定排序**。

**5. 最坏会退化**

若所有元素挤进同一个桶，就退化成"一次桶内排序"：本实现用 `Collections.sort` 是 O(n log n)；若桶内改用插入排序，则最坏 O(n²)。所以桶排序的快慢强依赖"分布均匀"这个前提。

---

### 复杂度

| | 平均 | 最坏 | 说明 |
|---|---|---|---|
| 时间 | O(n + k) | O(n²)（全挤一桶、桶内插入排序）| k 为桶数；均匀分布时近似 O(n) |
| 空间 | O(n + k) | O(n + k) | 需要桶数组及桶内存储 |

> 桶排序是"分配 + 各击破"：把大范围拆分到小桶里分别排序，靠**分布均匀**把每桶规模压到常数，从而突破比较排序下界。数据严重倾斜时优势尽失。

> **记忆口诀**：桶排序先归一化再乘 n 定桶，撒进去各桶排序，按桶号从小到大倒回；均匀才快，倾斜退化
