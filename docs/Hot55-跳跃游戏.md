# 算法笔记：跳跃游戏（力扣 55 题）

## 题目描述
给你一个非负整数数组 `nums` ，你最初位于数组的 **第一个下标** 。

数组中的每个元素代表你在该位置可以跳跃的 **最大长度** 。

判断你是否能够到达 **最后一个下标** 。

> 📌 关键理解：`nums[i]` 是「**最多**能跳这么远」，即在位置 `i` 你可以跳 `1 ~ nums[i]` 之间的**任意**步数（含直接跳过若干格），**不是必须**恰好跳 `nums[i]` 步。正因为可以“少跳”，贪心才有意义——站在任意可达位置都等价于站在 `maxStep` 覆盖范围内的最优点。

---

## 解法：贪心算法（Greedy）

### 1. 核心思想
不必关心“具体怎么跳”，只需关心“**最远能跳到哪**”。用一个变量 `maxStep` 记录从起点出发、经过当前及之前所有**可达位置**后，能够到达的**最远下标**。
* 遍历到位置 `i` 时，如果 `i > maxStep`，说明当前位置根本**够不着**，直接返回 `false`。
* 否则用“从这里最远能跳到 `i + nums[i]`”去更新边界：`maxStep = max(maxStep, i + nums[i])`。
* 一旦 `maxStep` 覆盖了终点下标 `n - 1`，即可提前返回 `true`。

> 贪心点：每走到一个可达位置，就把可达范围撑到最大。局部每一步都扩张边界，全局自然能判断终点是否被覆盖。

### 2. 代码实现 (Java)
把唯一的失败判断 `i > maxStep` 放在循环开头，整体流向符合“先确认够得着，再更新最远边界”的直觉。

```java
class Solution {
    public boolean canJump(int[] nums) {
        int n = nums.length;
        int maxStep = 0; // 目前能到达的最远下标

        for (int i = 0; i < n; i++) {
            // 当前位置已超出能到达的最远处，说明够不着这里
            if (i > maxStep) {
                return false;
            }

            // 从 i 出发最远能到 i + nums[i]，打擂台更新最远边界
            maxStep = Math.max(maxStep, i + nums[i]);

            // 最远边界已经覆盖终点，提前成功
            if (maxStep >= n - 1) {
                return true;
            }
        }

        // 兜底情况：如果遍历完没有返回 false，则说明一定可以到达终点，只给编译器看，无实际意义
        return true;
    }
}
```

### 3. 复杂度分析
* **时间复杂度**：$O(n)$。只需对数组进行一次遍历。
* **空间复杂度**：$O(1)$。只使用了 `maxStep` 一个额外变量。

### 4. 遍历过程图解

以成功用例 `nums = [2,3,1,1,4]`（n=5，终点下标 4）为例：

```text
i    nums[i]    i > maxStep?    maxStep = max(maxStep, i+nums[i])    ≥ n-1?
0       2            否                 max(0, 0+2) = 2                否
1       3            否                 max(2, 1+3) = 4                是 → true
```

> 第 2 步 `maxStep` 已达 4（终点下标），提前返回 `true`。

再看失败用例 `nums = [3,2,1,0,4]`：

```text
i    nums[i]    i > maxStep?    maxStep = max(maxStep, i+nums[i])    ≥ n-1?
0       3            否                 max(0, 0+3) = 3                否
1       2            否                 max(3, 1+2) = 3                否
2       1            否                 max(3, 2+1) = 3                否
3       0            否                 max(3, 3+0) = 3                否
4       4         是 (4 > 3) → false
```

> 关键：走到 `i=4` 时 `i > maxStep`（最远只能到下标 3），说明被下标 3 的 `0` 卡住，够不着终点。

### 5. 概念澄清：`maxStep` 是“最远下标”而非“步数”

容易把 `maxStep` 误解为“还能跳几步”，但它记录的是**能到达的最远下标**，这与“剩余步数”有本质区别：

| | 本题 `maxStep` | 若误解为“剩余步数” |
| :--- | :--- | :--- |
| 含义 | 从起点出发能到达的**最远下标** | 当前还剩几步可跳 |
| 更新式 | `max(maxStep, i + nums[i])` | 需每步 `-1` 再取 max，易错 |
| 失败判据 | `i > maxStep`（够不着） | 剩余步数 `< 0` |

**为何判据是 `i > maxStep`：** `maxStep` 是可达范围的右边界，一旦遍历下标 `i` 越过这个边界，就意味着中间某个位置值为 `0` 把路彻底堵死，后面再也走不动。

---

## 💡 总结

跳跃游戏是**贪心“覆盖范围”思想**的经典模板：把“能否到达终点”转化为“最远可达下标是否覆盖终点”，从而避开枚举所有跳法的指数级搜索。

| 特性 | 说明 |
| :--- | :--- |
| **思维出发点** | 关注**全局可达范围**，每到一个可达位置就把边界撑到最大。 |
| **代码表现** | 用 `if (i > maxStep) return false` 截断，用 `Math.max` 扩张边界。 |
| **时间 / 空间** | $O(n)$ / $O(1)$，一次遍历、单变量。 |

> ⚠️ 本题只求“能否到达”，贪心一趟 $O(n)$ 即可；若追问“最少跳几步”（跳跃游戏 II），则需另设 `end` / `farthest` 双边界按层贪心计数，思路同源但边界更多。
