# 算法笔记：多数元素（力扣 169 题）

## 题目描述
给定一个大小为 `n` 的数组 `nums`，返回其中的**多数元素**——即出现次数**大于** `⌊n/2⌋` 的元素。你可以假设数组非空且多数元素总是存在。

```
输入：nums = [2,2,1,1,1,2,2]
输出：2（出现 4 次 > 7/2 = 3）

输入：nums = [3,2,3]
输出：3
```

> 📌 关键理解："出现次数超过一半"是一个**极强的承诺**——多数元素比其余所有元素加起来还多。三个解法都在利用这一点：投票法是"一对一抵消，多数必剩"，排序法是"占过半席位必坐中位"，哈希法是"数到过半直接宣布"。若没有这个保证（如力扣 229 的 n/3），前两个结论都不再成立。

---

## 方法一：Boyer-Moore 投票法（推荐）

### 核心逻辑
维护一个候选人 `candidate` 和票数 `count`，一路走账：

* `count == 0`：上一轮抵消干净，换新候选人并把票置 1；
* 与候选人**相同**：`count++`（拉一票）；
* 与候选人**不同**：`count--`（同归于尽，一换一）。

多数元素出现次数 > n/2，任何其他元素都无法把它抵消干净，最终留下的候选必是它。

```
num:      2    2    2    1    3        （多数元素 2，3 次 > 5/2）
count:    1    2    3    2    1        ← 1、3 各换掉 2 一票，票从不归零，candidate 始终钉在 2
```

> 抵消视角：**反对者拉一个多数元素同归于尽**——反对者总数不到一半，换不完，多数元素必有剩余。

### 代码实现

```java
public int majorityElement_1(int[] nums) {
    int candidate = 0;
    int count = 0;
    for (int num : nums) {
        if (count == 0) {
            // 上一轮抵消干净，换新候选人；count 必须同时置 1，否则永远困在 0
            candidate = num;
            count++;
        } else if (num == candidate) {
            count++;
        } else {
            count--;  // 异己一票换多数一票
        }
    }
    return candidate;
}
```

## 方法二：排序取中位

### 核心逻辑
多数元素占据**超过一半**的席位，排序后区间 `[⌊n/2⌋]` 这个中位位置无论如何都落在它的领地内——从最左端或最右端数过来都过半。

```
[1,1,2,2,2]     → 中位 nums[2] = 2 ✓
[1,2,2,2,2]     → 中位 nums[2] = 2 ✓（多数挤满右半边）
[2,2,2,3,3,3,3] → 中位 nums[3] = 3 ✓（7 个里 3 占 4 > 3.5）
```

### 代码实现

```java
public int majorityElement_2(int[] nums) {
    Arrays.sort(nums);          // 原地排序，会修改入参
    return nums[nums.length / 2];  // 中位数一定是众数
}
```

## 方法三：哈希计数

### 核心逻辑
最朴素的暴力：`HashMap` 边遍历边累计次数，一旦某元素计数**严格大于** `n/2` 立刻返回（提前退出，不用扫完）。

### 代码实现

```java
public int majorityElement_3(int[] nums) {
    Map<Integer, Integer> map = new HashMap<>();
    for (int num : nums) {
        map.put(num, map.getOrDefault(num, 0) + 1);
        if (map.get(num) > nums.length / 2) return num;  // 过半即胜，提前退出
    }
    return -1;  // 题目保证存在，正常不可达，仅作兜底
}
```

## 复杂度对照

| 方法 | 时间 | 空间 | 是否修改入参 | 依赖"过半"保证 |
| :--- | :---: | :---: | :---: | :---: |
| **投票法** | $O(n)$ | $O(1)$ | 否 | 是 |
| **排序** | $O(n\log n)$ | $O(\log n)^*$ | **是**（原地 sort） | 是 |
| **哈希** | $O(n)$ | $O(n)$ | 否 | 是 |

\* `Arrays.sort` 基本类型走双轴快排，附加空间常记 $O(1)$，但递归栈实际 $O(\log n)$。

> **方法对比**：投票法在时间、空间上同时最优，是本题的"标准答案"；排序法代码最短但有 $O(n\log n)$ 代价 + 副作用；哈希法思路最直白，是没有任何性质保证时的通用底线（次数不定、不过半都得靠它）。

## 💡 总结
多数元素是**利用题目强承诺降维打击**的范例：同一道题，哈希 $O(n)$ 空间是通用解，投票 $O(1)$ 空间是技巧解——差距全在"超过一半"这四个字上。Boyer-Moore 投票法的"同加异减、归零换人"模板可直接迁移到 n/3、n/k 变体。

> 🔑 记忆口诀：**投票——同加异减归零换，剩者为王；排序——过半必坐中位；哈希——数过半即胜。**

> 🔧 相关变体：
> * **不保证多数元素存在**（剑指 Offer 17.10 等）：投票法只给出"候选"，需**第二遍遍历验证** `candidate` 的真实次数是否 > n/2，否则返回 -1。
> * **出现次数超过 ⌊n/3⌋**（力扣 229）：这样的元素**最多两个**，扩成两组 `candidate1/2 + count1/2`，抵消规则变为"谁都不匹配时两个计数同时减 1"，且候选需去重；同样必须事后验证。
> * **有序数组求众数**（力扣 1150）：过半性质 + 二分/双端检查即可。

> ⚠️ 易错点：
> 1. **【方法一】`count == 0` 分支换候选人后必须同时 `count = 1`**——只换人记账不置票，count 永远从 0 进分支、回不到正数，`candidate` 退化为"最后一个元素"（本题源码曾踩此坑，样例 `[3,2,3]` 恰好末位是众数而掩盖了 bug，反例 `[2,2,1]` 立刻返回错误的 1）。
> 2. **【方法一】题目保证存在才能直接返回 candidate**——无保证时投票结果可能是一个出现次数并不多的"幸存者"，必须二次验证。
> 3. **【方法二】`Arrays.sort` 原地修改入参**——调用方还需要原数组顺序时，先 `nums.clone()` 再排序。
> 4. **【方法三】判断用严格大于 `> n/2`**——写成 `>=` 会把"恰好一半"误判为多数（偶数长度时出错）。
> 5. **【通用】"多数"定义是 > ⌊n/2⌋**——与"众数（出现最多，可以并列/不过半）"不同，别混淆题意的适用范围。
