# 算法笔记：腐烂的橘子（力扣 994 题）

## 题目描述

每分钟，腐烂的橘子**上下左右四个方向相邻**的新鲜橘子都会腐烂。

返回直到单元格中没有新鲜橘子为止所必须经过的最小分钟数。如果不可能腐烂完所有橘子，返回 `-1`。

`0` 表示空单元格，`1` 表示新鲜橘子，`2` 表示腐烂的橘子。

```
输入: grid = [[2,1,1],
             [1,1,0],
             [0,1,1]]
输出: 4
```

---

## 核心思想

> **所有腐烂橘子同时起跑，每分钟向外扩散一层；答案就是"最后一块被传染到的新鲜橘子"等的层数。**

- 腐烂是**同时**发生的：第 t 分钟被传染的橘子 = 到某个初始腐烂橘子距离恰好为 t 的格子；
- 换句话说，每个新鲜橘子腐烂的时刻 = 它到**最近**腐烂橘子的距离（无权图最短路）；
- 求"多起点、同时出发、最少层数" → **多源 BFS**：把所有初始腐烂橘子当作第 0 层一起入队，逐层扩散，**扩散到第几层就是几分钟**；
- 用 `freshCount` 记录新鲜橘子数，传染一个减一个——既能 O(1) 判断"染完了该停"，也能在队列空时判断"有橘子永远染不到（返回 -1）"。

多源 BFS 有个经典等价理解：**建一个虚拟超级源点，连向所有初始腐烂橘子，再做单源 BFS**——层数（距离）不变。

---

## 图解：逐分钟扩散

```
初始:      第1分钟:    第2分钟:    第3分钟:    第4分钟:
2 1 1     2 2 1      2 2 2      2 2 2      2 2 2
1 1 0  →  2 1 0  →   2 2 0  →   2 2 0  →   2 2 0
0 1 1     0 1 1      0 1 1      0 2 1      0 2 2

fresh=6   fresh=4    fresh=2    fresh=1    fresh=0
```

第 0 层（初始腐烂橘子）不花时间；每处理一层 `minutes++`；`freshCount` 归零时停止，答案 4。

## 代码实现：多源 BFS (Java)

```java
public int orangesRotting(int[][] grid) {
    int rows = grid.length;
    int cols = grid[0].length;
    int freshCount = 0;                          // 新鲜橘子计数，传染时同步扣减
    Queue<int[]> queue = new LinkedList<>();

    // 第一遍扫描：腐烂橘子全部入队（多源 BFS 的"多源"），顺便数新鲜橘子
    for (int i = 0; i < rows; i++) {
        for (int j = 0; j < cols; j++) {
            if (grid[i][j] == 2) {
                queue.offer(new int[]{i, j});     // 腐烂橘子：第 0 层起点
            } else if (grid[i][j] == 1) {
                freshCount++;
            }
        }
    }

    // 没有新鲜橘子：0 分钟（含全空网格的情况）
    if (freshCount == 0) return 0;

    int[][] directions = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
    int minutes = 0;

    // freshCount > 0 是关键：最后一层染完就退出，minutes 不会多算一轮
    while (!queue.isEmpty() && freshCount > 0) {
        minutes++;                               // 每处理一层 = 过去一分钟
        int size = queue.size();                 // 锁住当前层，本层新入队的属于下一层
        for (int i = 0; i < size; i++) {
            int[] current = queue.poll();
            int row = current[0];
            int col = current[1];

            for (int[] direction : directions) {
                int newRow = row + direction[0];
                int newCol = col + direction[1];
                // 邻居是新鲜橘子才传染；入队的同时立刻标 2，防止被多个腐烂邻居重复入队
                if (newRow >= 0 && newRow < rows && newCol >= 0 && newCol < cols && grid[newRow][newCol] == 1) {
                    queue.offer(new int[]{newRow, newCol});
                    grid[newRow][newCol] = 2;
                    freshCount--;                 // 染一个记一个
                }
            }
        }
    }

    // 队列空了还有新鲜橘子 = 永远传染不到
    return freshCount == 0 ? minutes : -1;
}
```

## 为什么不用 DFS / 并查集？

### DFS：一条路走到底，量不出"最短时间"

- 传染是**所有方向同时向外扩一层**，本质是求**最短路**：每个新鲜橘子只关心到它**最近**的腐烂橘子有多远；
- DFS 一条路走到黑，得到的是**某一条**路径的长度，不是最短距离——用它算时间只会偏大；
- 退一步讲，就算对每个新鲜橘子单独跑 DFS 找最近腐烂橘子，也是 $O(mn)$ 个起点 × 每次全图搜索，复杂度直接爆炸；
- 选型口诀（见 Tip2）：**DFS 管"存不存在 / 走不走得通"，BFS 管"最少几步"**。无权图最短路天然是 BFS 的主场。

### 并查集：只会数"连不连通"，没有距离和时间

- 并查集回答的问题是"**这两个点在不在同一个连通块**"、"**图里有几个连通块**"（Hot200 数岛屿就是这么用的）；
- 本题要的是"**最后一块新鲜橘子第几分钟腐烂**"= 所有新鲜橘子到最近腐烂橘子距离的**最大值**——这是个**距离/层数**问题，合并集合的过程根本不产生距离信息；
- 就算只用并查集判断"哪些橘子最终能被传染到"（判 -1），求分钟数这半边活它也干不了。反过来，图一旦建好，并查集里"什么时候合并的"也不等于真实时间顺序。

一句话：**数连通块找并查集，找存在性找 DFS，算最少步数/时间找 BFS**——本题三个特征（多起点、同时扩散、求时间）全都指向多源 BFS。

## ❗关键易错点

**1. 多源必须"同时"入队**
所有初始腐烂橘子要在第一遍扫描时**一起**入队。如果逐个腐烂橘子分别做 BFS，各轮的分钟数会叠加而非并行，时间算错。

**2. `while` 条件里的 `freshCount > 0` 防止多算一分钟**
最后一层把橘子染完后，队列可能还剩几个节点没扩散。若只判 `!queue.isEmpty()`，会再空转一轮，`minutes` 多 1。

**3. 染色必须发生在"入队时"而不是"出队时"**
出队才标 2 的话，同一个新鲜橘子会被多个腐烂邻居重复入队，`freshCount` 被重复扣减，提前误判染完（和 Hot200 BFS 的"入队前淹没"同一个坑）。

**4. `freshCount == 0` 提前返回 0**
初始就没有新鲜橘子（甚至全空网格）答案是 0，不是 -1；这个判断也顺带覆盖了"没有腐烂橘子但有新鲜橘子"之外的正常情况。

**5. 返回 -1 的判定**
队列空了 `freshCount` 还 > 0 = 有橘子被空格/对角隔离，永远传染不到。

**6. 本题 grid 是 `int[][]`**
值是 `0/1/2` 的 int，别照搬 Hot200 的 `char[][]` 写成 `== '1'`。

## 复杂度分析

| 解法 | 时间 | 空间 | 说明 |
| :--- | :--- | :--- | :--- |
| 多源 BFS | $O(m \times n)$ | $O(m \times n)$ | 每个格子最多入队一次，队列最坏存全部格子 |
| 模拟法（每分钟全图扫描） | $O(k \times m \times n)$ | $O(1)$ | k 为答案分钟数；思路最直白（每轮把 2 旁边的 1 变 2），但每分钟重扫全图，k 大时明显吃亏 |

模拟法其实是多源 BFS 的朴素版：BFS 的队列就是"下一分钟要处理的橘子"名单，省掉了每分钟的全图扫描。
