# 数据流的中位数（Find Median from Data Stream）

## 题目描述

**中位数**是有序整数列表中间的数。如果列表长度是偶数，中位数则是中间两个数的平均值。

实现 `MedianFinder` 类：

- `MedianFinder()` 初始化对象
- `void addNum(int num)` 将整数 `num` 添加到数据流中
- `double findMedian()` 返回到目前为止所有元素的中位数

```
输入：
["MedianFinder", "addNum", "addNum", "findMedian", "addNum", "findMedian"]
[[], [1], [2], [], [3], []]
输出：
[null, null, null, 1.5, null, 2.0]

解释：
addNum(1)   → arr = [1]
addNum(2)   → arr = [1, 2]
findMedian()→ 1.5  ((1 + 2) / 2)
addNum(3)   → arr = [1, 2, 3]
findMedian()→ 2.0
```

> 进阶：如果数据流中所有整数都在 0 到 100 范围内，你将如何优化？如果 99% 的整数都在 0 到 100 范围内，你又将如何优化？

源码位置：[`../src/s13_dump/Hot295_MedianFinder.java`](../src/s13_dump/Hot295_MedianFinder.java)

## 核心思路

数据流是**动态插入**的，每次都要重新排序取中位数太贵（O(n log n)）。用一个经典的**对顶双堆**把数据劈成两半：

```
        左半（较小的一半）      |      右半（较大的一半）
        leftHeap 大顶堆        |      rightHeap 小顶堆
              ↓ 堆顶是左半最大值 | 堆顶是右半最小值 ↓
   ...  3  2  1               |              4  5  6  ...
             ▲                 |                 ▲
        中位数就藏在这两个堆顶之间
```

- **左堆（大顶堆）**：存较小的一半，堆顶 = 左半最大值。
- **右堆（小顶堆）**：存较大的一半，堆顶 = 右半最小值。
- **平衡约定**：让 `leftHeap` 可以比 `rightHeap` 多 1 个（奇数个元素时中位数放左堆顶）。

于是求中位数只看两个堆顶：

```
两堆不等（左多一个）→ 中位数 = leftHeap 堆顶
两堆相等            → 中位数 = (左堆顶 + 右堆顶) / 2.0
```

和 [`Hot215 数组中的第 K 个最大元素`](Hot215-数组中的第K个最大元素.md)、[`Hot347 前 K 个高频元素`](Hot347-前K个高频元素.md) 一样都是**堆的应用**，区别在于 295 用**两个方向相反的堆**夹住中位数，而不是单个堆做 Top K。

## 方法：对顶双堆

### addNum 逻辑

插入分两步——**先入堆，再平衡**：

```
第一步 选堆：
  左堆空 或 num ≤ 左堆顶 → 进左堆（属于较小的一半）
  否则                    → 进右堆

第二步 平衡（维持「左堆 = 右堆」或「左堆 = 右堆 + 1」）：
  左堆多超过 1 个 → 左堆顶挪到右堆
  右堆比左堆还多  → 右堆顶挪回左堆
```

先按大小归位、再用堆顶互相"倒腾"平衡，保证任意时刻左堆顶 ≤ 右堆顶（左半整体不超过右半）。

### 代码

```java
private PriorityQueue<Integer> leftHeap;   // 左半：大顶堆
private PriorityQueue<Integer> rightHeap;  // 右半：小顶堆

public Hot295_MedianFinder() {
    // 默认是小顶堆，用 lambda 自定义比较器 (b - a) 反转成大顶堆
    leftHeap = new PriorityQueue<>((a, b) -> b - a);
    rightHeap = new PriorityQueue<>();
}

public void addNum(int num) {
    // 1. 选堆：小的进左堆，大的进右堆
    if (leftHeap.isEmpty() || num <= leftHeap.peek()) {
        leftHeap.offer(num);
    } else {
        rightHeap.offer(num);
    }

    // 2. 平衡：保持 左堆 == 右堆 或 左堆 == 右堆 + 1
    if (leftHeap.size() > rightHeap.size() + 1) {
        rightHeap.offer(leftHeap.poll());   // 左堆太多，堆顶倒给右堆
    } else if (rightHeap.size() > leftHeap.size()) {
        leftHeap.offer(rightHeap.poll());   // 右堆反超，堆顶倒回左堆
    }
}

public double findMedian() {
    if (leftHeap.size() > rightHeap.size()) {
        return leftHeap.peek();             // 奇数个：左堆顶就是中位数
    }
    return (leftHeap.peek() + rightHeap.peek()) / 2.0;  // 偶数个：两堆顶求平均
}
```

> `findMedian` 里除以 `2.0`（而非 `2`）是关键：两个 `int` 相加若整除会丢失小数部分，`/ 2.0` 强制浮点运算才能返回 `1.5` 这样的结果。

### 复杂度

| 类型 | 复杂度 | 说明 |
|------|--------|------|
| addNum 时间 | O(log n) | 入堆 + 至多一次堆顶倒腾，都是堆操作 |
| findMedian 时间 | O(1) | 只读两个堆顶 |
| 空间 | O(n) | 两个堆合计存下全部 n 个元素 |

> 相比「每次插入都重新排序再取中位数」的 O(n log n)，双堆把单次插入压到 O(log n)，是数据流场景的标准解法。

## 插入过程图解

以 `addNum(1) → addNum(2) → addNum(3)` 为例：

```
addNum(1)：左空 → 进左堆；左1 右0，差 1 不越界
   左堆[1]   右堆[]      中位数 = 1

addNum(2)：2 > 左顶1 → 进右堆；左1 右1，平衡
   左堆[1]   右堆[2]     中位数 = (1+2)/2 = 1.5

addNum(3)：3 > 左顶1 → 进右堆；左1 右2，右反超 → 右顶2 倒回左堆
   左堆[2,1] 右堆[3]     中位数 = 左顶 2
```

每次插入后两堆大小始终维持在「相等」或「左多一」，中位数永远能从堆顶 O(1) 读出。

---

## 易错点

1. **左堆方向反了**：左半要**大顶堆**（`(a,b)->b-a`），右半要**小顶堆**（默认）。写反了堆顶就不是"夹住中位数的两个数"。
2. **除以 2 而非 2.0**：偶数个时 `(left + right) / 2` 是整数除法会截断，必须 `/ 2.0` 才返回正确的小数中位数。
3. **平衡条件的边界**：左堆最多只能比右堆多 1，判断是 `leftHeap.size() > rightHeap.size() + 1`，`+1` 漏写会导致左堆被过度倒空。
4. **右堆不能反超**：`rightHeap.size() > leftHeap.size()` 时要把右堆顶倒回左堆，否则奇数个时中位数会跑到右堆，`findMedian` 取左堆顶就错了。
5. **选堆用左堆顶比较**：`num <= leftHeap.peek()` 进左堆，别忘了左堆可能为空要先判 `isEmpty()`，否则 `peek()` 返回 null 拆箱 NPE。
6. **findMedian 空流未防**：本实现假定调用时至少有一个元素（题目保证）；若需健壮性应先判两堆是否皆空。
