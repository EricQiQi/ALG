# 算法笔记：寻找重复数（力扣 287 题）

## 题目描述
给定一个 `n + 1` 个整数的数组 `nums`，其中每个整数都在 `1 ~ n` 范围内（含 `1` 和 `n`）。已知**其中恰好存在一个重复的数字**（它可能出现 2 次或更多次），找出它。

**限制条件（本题的灵魂）**：
* 不能修改原数组；
* 只能使用 $O(1)$ 额外空间；
* 时间复杂度应小于 $O(n^2)$。

```
输入：nums = [1,3,4,2,2]
输出：2

输入：nums = [3,1,3,4,2]
输出：3
```

> 📌 关键理解：`n+1` 个数、值只有 `1~n` 这 `n` 种——**格子比坑多一个，必有一个坑挤俩**，重复数一定存在。而"不许改数组 + 不许用空间"等于明说：别数数了，看结构。把"下标 `i` 格子里写的数"当成"下一跳去几号格"，从 0 号格一路跳，`n+1` 个格子只有 `n` 种去向，一定有**两格写着同一个去向**——两路汇合就成圈，**圈的入口就是那个被写了两次的数**。

## 方法一：快慢指针（把数组当环形链表走）

对应源码：[findDuplicate_1](../src/s17_skill/Hot287_findDuplicate.java)

### 核心逻辑

**第 1 步：把数组跳成一条带圈的路线**

```text
nums = [1,3,4,2,2]，读法："我在几号格，就跳到格子上的数指引的格"

  0 → 1 → 3 → 2 → 4
              ↑     │
              └─────┘        跳到 2、4 来回转，圈入口 = 2 = 重复数 ✓

为什么入口偏偏是重复数：只有被写在两个格子里的数，才会有"两条路同时指进它"；
一条路线里能出现"汇合"的地方，只能是这种被写了两次的格子。
```

**第 2 步：慢的走 1 格、快的走 2 格，圈内必相遇**
路线迟早掉进圈里；在圈里快的一圈只比慢的多进 1 格，总能追上（套圈），记下相遇点。

**第 3 步：把慢的拽回起点，两个都改走 1 格，再遇 = 圈入口**
为什么拽回起点重走能停在入口？看距离关系：

```text
设：起点 → 入口 距离 a；   入口 → 相遇点（顺着走）距离 b；   圈长 L

相遇瞬间：慢走了 (a+b)，快是它的 2 倍，多出来的恰好是整数圈：
        (a+b)×2 − (a+b) = a+b = k×L        （k 为正的整数）

现在两个都走 1 格：
   慢从起点走 a 步        → 到入口
   快从相遇点走 a 步      → 顺圈走 a = k×L − b，即转 k 圈再倒 b，也正好是入口
   俩在入口碰面，锁定了 ✓
```

一句话版本：**相遇点沿圈"还差一圈回到入口"的距离，恰好等于起点到入口的距离**——所以从两头同时一格一格走，必在入口会师。

### 代码片段

```java
public int findDuplicate_1(int[] nums) {
    int slow = nums[0];
    int fast = nums[0];

    // 快慢指针找相遇点（起点相同，必须 do-while 先进一次循环）
    do {
        slow = nums[slow];            // 走 1 格
        fast = nums[nums[fast]];      // 走 2 格：先按格上的数跳一次，再跳第二次
    } while (slow != fast);

    // 慢的拽回同一个起点，之后两边都走 1 格，再相遇处 = 圈入口 = 重复数
    slow = nums[0];
    while (slow != fast) {
        slow = nums[slow];
        fast = nums[fast];
    }
    return slow;
}
```

## 方法二：对"数轴"二分（数坑法）

对应源码：[findDuplicate_2](../src/s17_skill/Hot287_findDuplicate.java)

### 核心逻辑
二分的对象**不是数组，是数值范围 `1~n` 这条数轴**。核心问题换成："重复的那个数，在数轴的左半还是右半？"

判据（抽屉原理）：`1~mid` 一共就 `mid` 个数，如果没有重复，数组里 `≤ mid` 的**最多也只能数出 mid 个**；一旦**数出超过 mid 个**，说明有数挤重了，重复数必在 `1~mid`（左半），否则在右半。

```text
nums = [1,3,4,2,2]，数轴 1..4

mid=2：≤2 的有 3 个(1,2,2) > 2   → 重复在左，收缩到 1..2
mid=1：≤1 的有 1 个(1)    = 1 不超 → 重复在右，收缩到 2..2
左==右==2 → 答案 2 ✓
```

### 代码片段

```java
public int findDuplicate_2(int[] nums) {
    int left = 1, right = nums.length - 1;      // 二分对象：值域 1..n
    while (left < right) {
        int mid = left + (right - left) / 2;
        int count = 0;
        for (int num : nums) {                  // 数一遍有几个落在 1..mid
            if (num <= mid) count++;
        }
        if (count > mid) right = mid;           // 超了 → 重复在左半
        else left = mid + 1;                    // 没超 → 在右半
    }
    return left;
}
```

## 复杂度对照

| 方法 | 时间 | 空间 | 改数组 | 思路门槛 |
| :--- | :---: | :---: | :---: | :--- |
| **快慢指针** | $O(n)$ | $O(1)$ | 否 | 高（要看出"值当下标跳"的圈结构） |
| **数轴二分** | $O(n\log n)$ | $O(1)$ | 否 | 低（数个数 + 二分，十分钟能推出来） |

> **方法对比**：两个都满足全部限制，快慢指针是"满分标准解"；二分是"好想好写的替补"——代价是每轮判据都要整趟数数组，慢一个 $\log n$。被限制卡掉的思路：**哈希计数** $O(n)$ 空间、**排序**改数组、**逐对比较** $O(n^2)$ 时间，各违反一条限制，只值部分分。

## 💡 总结
本题的钥匙是题面那三条限制，它们在暗示：**数组本身就是指针**。值域恰好是 `1~n`、个数却多一个，"把格子里的数当下一跳"必然走出一个圈，圈入口就是重复数——这套"数组模拟链表 + 相遇后拽回起点"与 142 环形链表 II 一模一样，会那道就会这道。想不出圈结构，就用数轴二分 + 抽屉原理兜底。

> 🔑 记忆口诀：**值当下标跳，必进圈；相遇拽回起点，一步一格再遇就是入口**——**数 ≤ mid 的超过 mid 个，重复在左边**。

> 🔧 相关变体：
> * **141 / 142 环形链表 I、II**：同一套快慢指针，142 的"第二次相遇在入口"和本题第 3 步完全同构；本题等于把链表藏进了数组里。
> * **允许改数组 / 用位图**：符号标记法 $O(n)/O(1)$（但要求可写）、哈希 $O(n)/O(n)$（但要求空间）——本题恰好都不许用。
> * **找所有重复数**（不止一个重复时）：快慢指针和数轴二分都失效（结果不再是唯一圈入口/唯一过半区间），得用哈希或排序类方法。

> ⚠️ 易错点：
> 1. **【方法一】第一段必须 `do-while`**——`slow`、`fast` 初值相同，写成 `while` 条件一次都不进，原地"已相遇"，后面全错。
> 2. **【方法一】拽回的起点必须是第一次出发的同一个位置**——从 `nums[0]` 出发就拽回 `nums[0]`（从 0 出发拽回 0 也行，两种都对）；两头不一致，"距离=整数圈"的关系就断了。
> 3. **【方法一】第二阶段 fast 必须改成走 1 格**——还按每次 2 格跑，第二次相遇点不是圈入口。
> 4. **【方法二】判据是严格大于 `count > mid`**——没重复时 `≤ mid` 的最多正好 `mid` 个，相等说明"没挤超"，重复在右边；写成 `>=` 会把"刚好填满"的也当成挤超往左收，可能把含重复的右半砍掉。
> 5. **【方法二】二分的是数轴不是下标**——数组是无序的且不许排序，不存在"左小右大"的边界；每次判断都要整趟数过去（$O(n)$），这是它比快慢指针慢的原因，别顺手写成拿 `nums[mid]` 和 `mid` 比较。
> 6. **【两法通用】"值域 1~n + 只有一个重复数"是前提**——少了任何一条（比如出现两个不同的重复数），圈结构或二分判据就不成立，得换通用方法。
