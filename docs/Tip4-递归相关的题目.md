# 递归

## 一、递归的本质

递归 = **拆问题** + **拼结果**

```
递归(大问题) {
    1. 终止条件 → 小到能直接回答
    2. 拆 → 把大问题拆成更小的同类问题（调用自己）
    3. 拼 → 用小问题的答案拼出大问题的答案
}
```

> 核心心法：**不要试图在脑中展开递归栈**，只需相信：子问题能解决，我只管写好"当前层做什么"。

---

## 二、递归三板斧

| 要素 | 说明 | 易错点 |
|------|------|--------|
| **终止条件** | 递归到什么时候停 | 漏写 → 栈溢出 |
| **拆解** | 调用自身，参数更小 | 参数没变小 → 无限递归 |
| **拼接** | 用子问题的返回值构造当前层的答案 | 忘了用返回值 / 返回值用错 |

## 三、递归的四大模式（从已做题目中提炼）

### 模式1：树的遍历 — 最经典的递归入门

> 对每个节点："我先处理自己，再递归左子树，再递归右子树"（顺序不同 = 前/中/后序）

| 题目 | 递归做什么 | 终止条件 |
|------|-----------|---------|
| **94** 二叉树遍历 | 左→根→右（中序） | `node == null` |
| **104** 最大深度 | `max(左深度, 右深度) + 1` | `node == null → 0` |
| **226** 翻转二叉树 | 递归翻左右子树，然后交换 | `node == null` |
| **543** 二叉树直径 | 递归求深度时顺带更新最大直径 | `node == null → 0` |
| **98** 验证BST | 递归时传递合法值范围 `(min, max)` | `node == null → true` |
| **108** 有序数组转BST | 取中间值做根，递归建左右子树 | `left > right → null` |
| **101** 对称二叉树 | 递归遍历对比左右子树 | `node == null` |

**套路总结：**
```
int dfs(TreeNode node) {
    if (node == null) return 基础值;     // 终止
    int left  = dfs(node.left);          // 拆
    int right = dfs(node.right);         // 拆
    return 用 left, right 拼出答案;      // 拼
}
```

### 模式2：链表的递归 — "相信后面的兄弟能搞定"

> 关键思维：**我只管当前节点，剩下的递归帮我处理**

| 题目 | 递归思路 | 终止条件 |
|------|---------|---------|
| **206** 反转链表 | 递归反转 `head.next`，然后 `head.next.next = head` | `head == null \|\| head.next == null` |
| **24** 两两交换 | 递归交换后面的节点，再连接当前两个 | `head == null \|\| head.next == null` |
| **25** K个一组翻转 | 反转前k个，递归处理剩余部分，拼接 | 剩余不足k个 → 直接返回 |

**套路总结（以206为例的思维链）：**
```
假设 reverseList(head.next) 已经帮我把后面的都反转了：
    head.next 现在是尾部
    让 head.next.next = head  → 把当前节点接到尾部
    让 head.next = null       → 当前节点变成新尾部
    返回递归拿到的新头
```

> 链表递归的核心：**不要想整条链表怎么翻，只想"当前节点"和"下一个节点"的关系**。

---

### 模式3：分治 — 大问题切两半，各自递归，合并结果

> 特征：问题规模用 `(left, right)` 区间表示，每次二分

| 题目 | 怎么分 | 怎么合 |
|------|-------|-------|
| **148** 链表排序 | 快慢指针找中点，断开成两半 | 合并两个有序链表 |
| **23** 合并K个有序链表 | k个链表二分，每次分成两组 | 合并两个有序链表 |
| **归并排序** | 数组二分 | 合并两个有序区间 |
| **快速排序** | partition 分成 ≤pivot 和 >pivot | 不需要合，排完即有序 |

**套路总结：**
```
T(问题) {
    if (问题足够小) return 直接解决;     // 终止
    int mid = 分界点;                    // 分
    T(左半);                             // 治
    T(右半);                             // 治
    merge(左结果, 右结果);               // 合
}
```

---

### 模式4：递归 + 记忆化 — 避免重复计算

| 题目 | 递归做什么 | 记忆化什么 |
|------|-----------|-----------|
| **138** 复制带随机指针链表 | 递归复制 `next` 和 `random` | 用 HashMap 缓存已复制的节点，避免重复创建 |

## 五、递归解题 Checklist

拿到一道题，问自己三个问题：

1. **终止条件是什么？** → 参数为 null / 区间长度为0 / 特定边界
2. **当前层做什么？** → 用一句话描述（不算递归调用）
3. **递归的返回值怎么用？** → 当前层要用子问题的返回值做什么

能回答这三个问题，递归就写出来了。

## 六、递归 vs 迭代 对照

| 题目 | 递归写法 | 迭代写法 | 备注 |
|------|---------|---------|------|
| 206 反转链表 | 3行核心代码 | 需要 prev/curr/next 三个指针 | 递归更简洁 |
| 94 二叉树遍历 | 5行 | 需要栈模拟 | 递归更直观 |
| 102 层序遍历 | 不自然 | BFS队列 | **迭代更合适** |
| 148 链表排序 | 自顶向下归并 | 自底向上归并可优化到O(1)空间 | 各有优势 |

> 递归不是万能的。**树的DFS用递归天然合适，BFS用迭代更自然**。
