# LeetCode 20. 有效的括号

对应源码：[Hot20_isValid.java](../src/s12_stack/Hot20_isValid.java)

## 题目描述

给定一个只包括 `(`、`)`、`{`、`}`、`[`、`]` 的字符串 `s`，判断字符串是否有效。有效字符串需满足：

1. 左括号必须用**相同类型**的右括号闭合
2. 左括号必须以**正确的顺序**闭合
3. 每个右括号都有一个对应的相同类型的左括号

```
"()"      → true        "()[]{}"  → true
"(]"      → false       "([)]"    → false      （顺序错乱）
"{[]}"    → true        "())"     → false      （右括号多余）
"("       → false       "(("      → false      （左括号多余）
```

## 💡 大白话解析

括号匹配的本质是**「最近未闭合的左括号，必须最先被闭合」**——这就是后进先出，天生用栈。

本题的巧妙之处在于**压栈时不压左括号本身，而是压它「期望的右括号」**：

- 读到 `(` → 压 `)`
- 读到 `[` → 压 `]`
- 读到 `{` → 压 `}`

这样一来，遇到右括号时**只需一次 `peek() == c` 比较**就能判断是否匹配，省掉了"弹出左括号 → 再查映射表 → 比较"的三步。栈顶元素直接就是「现在最想要的那个字符」。

三种情况的处理：

| 读到的字符 | 动作 |
| :--- | :--- |
| 左括号 | 压入对应的期望右括号 |
| 右括号，且等于栈顶 | 匹配成功，弹栈 |
| 右括号，但栈空或不等于栈顶 | **立即 return false** |

遍历结束后，栈必须为空——否则说明有左括号一直没被闭合。

## 图解

以 `"{[()]}"` 为例（栈按 底→顶 排列）：

```
读到    动作                栈（底→顶）
 {      push '}'            }
 [      push ']'            } ]
 (      push ')'            } ] )
 )      == 栈顶，pop        } ]
 ]      == 栈顶，pop        }
 }      == 栈顶，pop        （空）

遍历结束 → 栈空 → true ✓
```

**嵌套结构在栈里表现为「压进去的顺序正好是弹出来的逆序」**，这就是为什么 `([)]` 会被判 false：读到 `)` 时栈顶是 `]`，对不上。

## 💻 Java 代码实现

```java
public boolean isValid(String s) {
    Deque<Character> deque = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(') {
            deque.push(')');                    // 压入"期望的右括号"
        } else if (c == '[') {
            deque.push(']');
        } else if (c == '{') {
            deque.push('}');
        } else if (!deque.isEmpty() && deque.peek() == c) {
            deque.pop();                        // 匹配成功
        } else {
            return false;                       // 栈空 或 类型不匹配，直接失败
        }
    }
    return deque.isEmpty();                     // 有左括号剩余则无效
}
```

> ⚠️ 当前源码缺少最后那个 `else return false;` 分支，详见下方**易错点 1**。

## 复杂度分析

| 指标 | 复杂度 | 说明 |
| :--- | :---: | :--- |
| 时间 | O(n) | 每个字符进出栈各至多一次 |
| 空间 | O(n) | 最坏情况全是左括号，栈深 n |

## ⚠️ 易错点

### 1. 缺少 `else return false;`（当前源码的缺陷）

右括号"对不上"时如果没有兜底分支，程序会**静默跳过这个字符**继续循环，最后仅凭栈是否为空来判定。反例：

```
输入 "())"：
  (   → push ')'        栈：)
  )   → == 栈顶，pop    栈：（空）
  )   → 栈空，四个分支全不命中 → 被忽略 ❌ 此处应 return false
  遍历结束 isEmpty() → 返回 true（正确答案是 false）
```

实测受影响的用例：`"())"`、`"()))"`、`"(])"` 全部误判为 `true`。

> 注意 `"([)]"` 侥幸返回 `false`，是因为栈里残留了 `'('`，**不是逻辑正确**。

### 2. 结尾必须 `return deque.isEmpty()`，不能 `return true`

漏掉这一步会让 `"((("`、`"([]"` 这类**左括号有剩余**的输入被判为有效。

### 3. `!isEmpty()` 必须写在 `peek()` 前面

```java
} else if (!deque.isEmpty() && deque.peek() == c) {   // ✓ 短路保护
} else if (deque.peek() == c && !deque.isEmpty()) {   // ✗ 空栈时 NPE
```

`ArrayDeque.peek()` 在空栈时返回 `null`，而 `c` 是基本类型 `char`，`Character == char` 会触发**自动拆箱**，对 `null` 拆箱直接抛 `NullPointerException`。依赖 `&&` 的短路特性才能避免。

### 4. 别用 `java.util.Stack`

`Stack` 继承自 `Vector`，每个方法都带 `synchronized`，性能差且 API 陈旧。统一用 `Deque` + `ArrayDeque`，详见 [Queue、Deque、Stack](Tip5-Queue、Deque、Stack.md)。

### 5. `ArrayDeque` 不允许存 `null`

所以「用 `null` 占位」的思路在这里行不通；反过来，`peek()` 返回 `null` 也就成了判断空栈的信号。

## 🧠 方法对比

| 方法 | 思路 | 优劣 |
| :--- | :--- | :--- |
| **压期望右括号**（本文） | 左括号进栈时就翻译成对应的右括号 | 匹配时只比一个字符，无需额外数据结构，**最简洁** |
| HashMap 映射 | `map = {')':'(', ']':'[', '}':'{'}`，遇右括号查表比对弹出的左括号 | 括号种类多时易扩展，但多一次哈希查找和一个 map 的空间 |
| 计数器 | 用一个 int 记录未闭合数量 | **只适用于单一括号类型**；`"([)]"` 这种交叉顺序会漏判 |

面试推荐第一种，写起来短、讲起来清楚；被追问"括号种类变多怎么办"时，再切到 HashMap 映射法。

## 🧠 记忆口诀

> **左括号进栈变右括号，右括号进栈比栈顶；对不上就 false，走完看栈空。**
