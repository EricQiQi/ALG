# Arrays.sort 原理详解

Java 的 `Arrays.sort()` 是**分而治之**思想的典型应用。它会根据数据类型和数组规模，自动选择最优的排序算法。

---

## 一、基础：快速排序（QuickSort）

要理解 `Arrays.sort`，必须先懂快速排序。

### 核心思想

1. 从数组中选一个元素作为**基准值（pivot）**
2. 把数组分成两部分：**比 pivot 小的放左边，比 pivot 大的放右边**
3. 对左右两部分**递归**执行同样的操作
4. 当所有子区间都排好序时，整个数组就有序了

### 示例

```
数组: [5, 3, 8, 1, 9, 2]，选 pivot = 5

第一轮划分:
[3, 1, 2]   [5]   [8, 9]
   ↓         ↓       ↓
递归排序   基准就位  递归排序

结果: [1, 2, 3, 5, 8, 9] ✅
```

### 复杂度

| 情况 | 时间复杂度 |
|------|-----------|
| 最好/平均 | O(n log n) |
| 最坏（已排序数组） | O(n²) |

---

## 二、Java 的实际实现（分情况讨论）

`Arrays.sort()` 并不是一种算法，而是**多种算法的智能组合**：

### 1️⃣ 基本类型数组（int[]、char[] 等）

使用 **双轴快速排序（Dual-Pivot QuickSort）**

```
选取两个基准值 pivot1 和 pivot2（pivot1 ≤ pivot2）
把数组分成三段：
   [ < pivot1 ] [ pivot1 ~ pivot2 ] [ > pivot2 ]
对三段分别递归排序
```

**为什么用双轴？** 比普通快排多一次划分，递归深度更浅，实际运行更快。

### 2️⃣ 对象数组（String[]、Integer[] 等）

使用 **TimSort**（归并排序的优化版），因为对象排序需要**稳定性**（相等的元素保持原顺序）。

### 3️⃣ 小数组优化（元素个数 < 47）

直接使用**插入排序**，因为小数组插入排序的常数因子更小，比快排更快。

---

## 三、在字母异位词题目中的实际执行过程

回到 s1_hash.Hot49_groupAnagrams 这道题，`s = "eat"` 时：

```java
char[] arr = s.toCharArray();   // arr = ['e', 'a', 't']
Arrays.sort(arr);               // 对字符数组排序
```

执行步骤：

```
['e', 'a', 't']
   ↓ 双轴快排（3个元素，实际走插入排序）
比较 'e' 和 'a' → 交换 → ['a', 'e', 't']
比较 'e' 和 't' → 不交换
   ↓
['a', 'e', 't'] ✅
```

**时间复杂度：O(k log k)**，k 是字符串长度。

## 四、一张图总结

```
Arrays.sort(arr)
    │
    ├── 基本类型? ──→ 双轴快速排序（不稳定，快）
    │                    │
    │                    └── 小数组（<47）→ 插入排序
    │
    └── 对象类型? ──→ TimSort（稳定，归并优化）
```

## 五、稳定性对比

| 算法 | 稳定性 | 时间复杂度 | 空间复杂度 |
|------|--------|-----------|-----------|
| 双轴快速排序 | ❌ 不稳定 | O(n log n) | O(log n) |
| TimSort | ✅ 稳定 | O(n log n) | O(n) |
| 插入排序 | ✅ 稳定 | O(n²) | O(1) |

> **稳定性**：相等的元素在排序后保持原来的相对顺序。

# Java 算法笔记：区间排序语法与防溢出指南

在解决诸如**合并区间（力扣 56）**、**无重叠区间（力扣 435）**等二维数组/区间类问题时，我们通常需要先对区间进行排序。在 Java 中，有几种不同的排序写法，它们的底层逻辑和安全性各有不同。

---

## 核心结论：两者的等价性

在 `Arrays.sort()` 中，以下两种写法在**底层比对逻辑**和**排序结果**上是**完全等价**的，且都能**完美避免整数溢出漏洞**：

```java
// 写法 A：使用 Comparator 构造器（现代 Java 推荐）
Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));

// 写法 B：使用传统的双参数 Lambda 表达式
Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
```

---

## 🔍 深度对比：它们有什么区别？

虽然结果相同，但它们的**职责**和**参数传递机制**截然不同：

### 1. 职责与参数差异
* **`Integer.compare(x, y)` 是一把具体的“剪刀”**：
  它是一个具体的工具方法，必须接收 **2 个具体的 int 参数**。你作为“裁判”，必须手动声明 `(a, b)`，并明确把 `a[0]` 和 `b[0]` 抓出来传给它。
* **`Comparator.comparingInt(提取规则)` 是一台“自动化机器人”**：
  它是一个构造器，用来**生成**一个比较器（Comparator）。它只需要 **1 个参数**（即提取规则 `a -> a[0]`）。你只需要告诉它：“以后看到任何一个区间 `a`，你就去揪出它的 `a[0]`。”至于怎么比、怎么传两个参数，机器人会在后台自动调用类似 `Integer.compare` 的逻辑帮你搞定。

### 2. 直观对比表

| 特性 | `Comparator.comparingInt(a -> a[0])` | `(a, b) -> Integer.compare(a[0], b[0])` |
| :--- | :--- | :--- |
| **本质** | 比较器构造器（声明式） | 传统 Lambda 表达式（命令式） |
| **参数数量** | **1 个**（只需定义如何从单条数据提取特征） | **2 个**（必须定义两条数据如何单调对决） |
| **代码可读性** | **极高**（一眼看出是“根据左端点排序”） | **中等**（需要读完整个相减或比对表达式） |
| **IDE 态度** | IDEA 极其推荐，会自动提示将后者重构为前者 | 属于基础写法，IDEA 会报优化警告 |

## ⚠️ 避坑：为什么不用 `(a, b) -> a[0] - b[0]`？

很多初学者喜欢写成相减的形式：
```java
// ❌ 存在致命安全隐患的写法
Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
```
**原因：隐藏的整数溢出（Integer Overflow）漏洞。**
减法是通过结果的正负来决定先后顺序的。如果数组中的数字非常大或者是负数，相减就会翻车：
* 假设 `a[0] = -2,000,000,000`（极小的负数），`b[0] = 2,000,000,000`（极大的正数）。
* 本来 `a[0]` 明显小于 `b[0]`，但它们相减：`-2,000,000,000 - 2,000,000,000`。
* 结果在计算机里会溢出反转，变成一个正数 `294,967,296`。
* 排序器会错误地认为 `a` 比 `b` 大，从而导致**排序结果彻底混乱**。

> **🌟 面试金律**：在力扣或面试中，涉及数值大小比较时，**永远优先使用 `Integer.compare()` 或 `Comparator.comparingInt()`**，绝对不要手写减号 `-`。

## 🚀 进阶：如何优雅地进行“多条件组合排序”？

在更高级的区间题目中（例如力扣 354. 俄罗斯套娃信封问题），面试官往往会提出更复杂的排序需求。利用 `Comparator` 强大的**链式调用**能力，我们可以用一行代码优雅地解决：

**需求**：
1. 优先按照区间的**左端点 `a[0]` 升序**排序；
2. 如果左端点相同，则按照**右端点 `a[1]` 降序**排序。

### 现代 Java 链式写法：
```java
Arrays.sort(intervals, Comparator.comparingInt((int[] a) -> a[0])
                                 .thenComparing((a, b) -> Integer.compare(b[1], a[1])));
                                 // 注意：b[1] 和 a[1] 颠倒位置即代表降序
```

### 传统 Lambda 写法（作为对照）：
```java
Arrays.sort(intervals, (a, b) -> {
    if (a[0] != b[0]) {
        return Integer.compare(a[0], b[0]); // 左端点不同，升序
    }
    return Integer.compare(b[1], a[1]);     // 左端点相同，右端点降序
});
```
**总结**：现代链式写法不仅有效避免了多层 `if-else` 的嵌套，而且极大地提升了算法代码的工程美感。
