# 👑 滑动窗口最大值：单调队列与分块 DP 双战神版指南

力扣 **239. 滑动窗口最大值（Hard）** 是一道著名的“披着羊皮的狼”。如果使用常规的滑动窗口在窗口内“翻箱倒柜”找最大值，时间复杂度会飙升至 $O(N \times K)$，在面对 $N=100,000$ 的大数据集时会**毫无悬念地超时（TLE）**。

要实现真正的 **$O(N)$ 硬件级速度**，行业内有两种统治级的写法语路：一种是利用**单调队列**进行无情内卷，另一种是利用**动态规划（DP）**进行分块查表。本篇文档为你将这两种战神级 Java 解法打包收录。

---

## 🏃 战神解法一：单调队列法（最强工具人：时间 $O(N)$，空间 $O(K)$）

这个解法通过引入一个双端队列（`Deque`），把窗口区域变成了一个**“职场内卷/长江后浪推前浪”**的游戏。

### 🎮 大白话核心机制
1. **帮规：严格单调递减**
   队列里存的是柱子的**下标（索引）**。从队头到队尾，对应的柱子高度必须是严格从大到小死死卡住的。队头永远坐着当前窗口的“带头大哥”（最大值）。
2. **新人入队（无情内卷）**
   新柱子（新人）进窗时，从队尾看过去。如果队尾的人**比新人都矮**，说明只要有新人在，那些又老又矮的人就永远不可能成为窗口最大值了。新人会无情地把队尾比他矮的人通通踢走（`pollLast()`），直到碰壁或队列空了才坐下。
   👉 *大白话：只要你比我新，还比我强，那你就把我内卷了，我可以当场退休了。*
3. **老大退役（年龄到期）**
   窗口右移，老大哥虽然很强，但他的物理位置可能已经滑出窗口了。检查队头大哥的下标，若发现落后于 `right - k + 1`，强制赶走退役（`pollFirst()`）。

### 💻 Java 代码实现
```java
import java.util.ArrayDeque;
import java.util.Deque;

public class SolutionQueue {
    public int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || nums.length == 0 || k <= 0) return new int[0];
        
        int n = nums.length;
        int[] ans = new int[n - k + 1]; // 结果数组
        int r = 0; // 结果数组指针
        
        // 核心武器：双端队列，用来维护“单调递减”的下标
        Deque<Integer> deque = new ArrayDeque<>();
        
        for (int right = 0; right < n; right++) {
            // 1. 【新人入队】：只要队尾的人比当前新人矮，通通踢走，无情内卷！
            while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[right]) {
                deque.pollLast();
            }
            
            // 2. 新人安全入队尾
            deque.addLast(right);
            
            // 3. 【老大退役】：如果队头大哥的下标已经过期（滑出窗口左边界），强制退役！
            if (deque.peekFirst() < right - k + 1) {
                deque.pollFirst();
            }
            
            // 4. 窗口正式成型（走了至少 k-1 步），队头就是无敌最大值
            if (right >= k - 1) {
                ans[r++] = nums[deque.peekFirst()];
            }
        }
        return ans;
    }
}
```

## 🧱 战神解法二：分块双向 DP 法（极致数学美：时间 $O(N)$，空间 $O(N)$）

如果你觉得单调队列的内卷逻辑、双端队列指针容易写出 Bug，那么这套基于**动态规划（DP）**思想的“分班双向扫描法”则是工程稳定性的神作。

### 🎮 大白话核心机制
1. **化整为零：划分小班级**
   既然几万人在大队伍里找老大很慢，我们把 10 万人按照每 $K$ 个人一组，分成一个个“小班级（块）”。
2. **两座单调大坝（状态转移方程）**
    * `left_max[i]`：记录从自己**班级开头**走到位置 `i` 的最强者。
      👉 `left_max[i] = (i % k == 0) ? nums[i] : Math.max(left_max[i - 1], nums[i])`
    * `right_max[i]`：从右往左倒着扫，记录从当前位置到自己**班级结尾**的最强者。
3. **降维打击：一秒查表**
   当一个滑动窗口跨越两个班级时（前半截在 A 班，后半截在 B 班）：
    * 跨在 A 班的这一截，最大值必定是 `right_max[left]`（从左端点到 A 班结尾的最大值）。
    * 跨在 B 班的这一截，最大值固定是 `left_max[right]`（从 B 班开头到右端点的最大值）。
    * 整个窗口的老大，直接就是两者的较大值：`Math.max(right_max[left], left_max[right])`！

### 💻 Java 代码实现
```java
public class SolutionDP {
    public int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || nums.length == 0 || k <= 0) return new int[0];
        int n = nums.length;
        int[] res = new int[n - k + 1];

        // 记账本：盖两座每 K 个元素自动断开重新筑基的分段大坝
        int[] left_max = new int[n];
        int[] right_max = new int[n];

        // 1. 正向状态转移：算出每个位置在自己班级里，从左到当前的最高分
        for (int i = 0; i < n; i++) {
            if (i % k == 0) {
                left_max[i] = nums[i]; // 班级第一个人
            } else {
                left_max[i] = Math.max(left_max[i - 1], nums[i]);
            }
        }

        // 2. 逆向状态转移：算出每个位置在自己班级里，从当前到结尾的最高分
        for (int i = n - 1; i >= 0; i--) {
            if (i == n - 1 || (i + 1) % k == 0) {
                right_max[i] = nums[i]; // 班级最后一个人
            } else {
                right_max[i] = Math.max(right_max[i + 1], nums[i]);
            }
        }

        // 3. 一键出答案：完全消灭嵌套循环，利用 DP 状态进行 O(1) 合并
        for (int i = 0; i < res.length; i++) {
            int left = i;
            int right = i + k - 1;
            res[i] = Math.max(right_max[left], left_max[right]);
        }

        return res;
    }
}
```

## 📊 双战神解法终极横向对比

| 维度 | 🏃 战神解法一（单调队列法） | 🧱 战神解法二（分块双向 DP 法） |
| :--- | :--- | :--- |
| **底层核心思想** | 贪心思想、实时维护单调递减队列 | **动态规划（DP）**、子问题预处理与状态合并 |
| **时间复杂度** | **$O(N)$**（每个下标最多进出队列各 1 次） | **$O(N)$**（三个独立的单层 `for` 循环） |
| **空间复杂度** | **$O(K)$**（队列最多同时存 $K$ 个元素） | $O(N)$（需要开辟两个长度为 $N$ 的大坝数组） |
| **编码复杂度** | 较高（需熟练操作双端队列头尾指针） | 极低（三个极其机械、工整的单层循环） |
| **边界条件坑** | 容易搞错滑出窗口的下标过期逻辑 | 几乎无坑，只需注意 `% k == 0` 的边界筑基 |
| **工程实用度** | 内存开销小，适合运行内存极度受限场景 | 稳定性强，代码无嵌套分支，对 CPU 分支预测极度友好 |

> 第一种是**单调队列的贪心内卷方案**。通过维护一个严格单调递减的双端队列，让新元素从队尾对不合规的过时元素进行淘汰，从而将空间复杂度死死卡在 $O(K)$。
>
