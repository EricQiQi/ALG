# 👑 滑动窗口最大值：单调队列与分块 DP 双战神版指南

力扣 **239. 滑动窗口最大值（Hard）** 是一道著名的“披着羊皮的狼”。如果使用常规的滑动窗口在窗口内“翻箱倒柜”找最大值，时间复杂度会飙升至 $O(N \times K)$，在面对 $N=100,000$ 的大数据集时会**毫无悬念地超时（TLE）**。

要实现真正的 **$O(N)$ 硬件级速度**，行业内有两种统治级的写法语路：一种是利用**单调队列**进行无情内卷，另一种是利用**动态规划（DP）** 进行分块查表。本篇文档为你将这两种战神级 Java 解法打包收录。

---

## 🏃 战神解法一：单调队列法（最强工具人：时间 $O(N)$，空间 $O(K)$）

这个解法通过引入一个双端队列（`Deque`），把窗口区域变成了一个 **“职场内卷/长江后浪推前浪”** 的游戏。

### 🎮 大白话核心机制
1. **帮规：严格单调递减**
   队列里存的是柱子的**下标（索引）**。从队头到队尾，对应的柱子高度必须是严格从大到小死死卡住的。队头永远坐着当前窗口的“带头大哥”（最大值）。
2. **新人入队（无情内卷）**
   新柱子（新人）进窗时，从队尾看过去。如果队尾的人**比新人都矮**，说明只要有新人在，那些又老又矮的人就永远不可能成为窗口最大值了。新人会无情地把队尾比他矮的人通通踢走（`pollLast()`），直到碰壁或队列空了才坐下。
   👉 *大白话：只要你比我新，还比我强，那你就把我内卷了，我可以当场退休了。*
3. **老大退役（年龄到期）**
   窗口右移，老大哥虽然很强，但他的物理位置可能已经滑出窗口了。检查队头大哥的下标，若发现落后于 `right - k + 1`，强制赶走退役（`pollFirst()`）。

### 💻 Java 代码实现
```java
import java.util.ArrayDeque;
import java.util.Deque;

public class SolutionQueue {
    public int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || nums.length == 0 || k <= 0) return new int[0];
        
        int n = nums.length;
        int[] ans = new int[n - k + 1]; // 结果数组
        int r = 0; // 结果数组指针
        
        // 核心武器：双端队列，用来维护“单调递减”的下标
        Deque<Integer> deque = new ArrayDeque<>();
        
        for (int right = 0; right < n; right++) {
            // 1. 【新人入队】：只要队尾的人比当前新人矮，通通踢走，无情内卷！
            while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[right]) {
                deque.pollLast();
            }
            
            // 2. 新人安全入队尾
            deque.addLast(right);
            
            // 3. 【老大退役】：如果队头大哥的下标已经过期（滑出窗口左边界），强制退役！
            if (deque.peekFirst() < right - k + 1) {
                deque.pollFirst();
            }
            
            // 4. 窗口正式成型（走了至少 k-1 步），队头就是无敌最大值
            if (right >= k - 1) {
                ans[r++] = nums[deque.peekFirst()];
            }
        }
        return ans;
    }
}
```

## 🧱 战神解法二：分块双向 DP 法（时间 $O(N)$，空间 $O(N)$）

这个解法不维护任何窗口，而是**提前把“块内的区间最大值”算好**，滑窗时只做查表。下面按步骤把它推出来。

### 第 1～4 步：思路关键点

1. **暴力的浪费**：相邻窗口有 `k - 1` 个元素重合，每次重扫整个窗口会重复计算，复杂度 $O(NK)$。
2. **固定切块**：从下标 0 开始，每 `k` 个元素一块，块边界固定在 `0, k, 2k, ...`，不随窗口移动（最后一块可能不足 k 个）。
3. **关键观察**：窗口长度 = 块长度 = k，所以任意窗口最多横跨两个相邻块，且正好等于「A 块的后缀 + B 块的前缀」；`left` 在块首时，窗口与一个块完全重合。
4. **预处理 + 查表**：
   - `left_max[i]`：块首 → i 的最大值（块内前缀），从左往右递推；
   - `right_max[i]`：i → 块末的最大值（块内后缀），从右往左递推；
   - 遇到块首/块末直接取 `nums[i]`，否则取 `max(前一个状态, nums[i])`；
   - 窗口 `[left, right]` 的答案 = `max(right_max[left], left_max[right])`。

### 第 5 步：完整手算推演

仍以 `nums = [1, 3, -1, -3, 5, 3, 6, 7]`、`k = 3` 为例。

**① 从左往右，算块内前缀最大值 `left_max`**

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| nums[i] | 1 | 3 | -1 | -3 | 5 | 3 | 6 | 7 |
| 是否块首 | ✓ | | | ✓ | | | ✓ | |
| left_max[i] | 1 | 3 | 3 | -3 | 5 | 5 | 6 | 7 |

- `i = 0, 3, 6` 是块首，直接取 `nums[i]`；
- 其余位置按 `left_max[i] = max(left_max[i - 1], nums[i])` 递推，例如 `left_max[4] = max(-3, 5) = 5`。

**② 从右往左，算块内后缀最大值 `right_max`**

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| nums[i] | 1 | 3 | -1 | -3 | 5 | 3 | 6 | 7 |
| 是否块末 | | | ✓ | | | ✓ | | ✓ |
| right_max[i] | 3 | 3 | -1 | 5 | 5 | 3 | 7 | 7 |

- `i = 2, 5, 7` 是块末，直接取 `nums[i]`；
- 其余位置按 `right_max[i] = max(right_max[i + 1], nums[i])` 递推，例如 `right_max[0] = max(right_max[1], 1) = max(3, 1) = 3`。

**③ 逐个窗口查表（表格直接写出每次查表的覆盖范围）**

| 窗口 | right_max[left] | 覆盖范围 | left_max[right] | 覆盖范围 | 两段并集 | 答案 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| i = 0：`[0,2]` = `[1,3,-1]` | `right_max[0] = 3` | `{0,1,2}`（left=0 → 块 A 尾=2） | `left_max[2] = 3` | `{0,1,2}`（块 A 头=0 → right=2） | `{0,1,2}` | **3** |
| i = 1：`[1,3]` = `[3,-1,-3]` | `right_max[1] = 3` | `{1,2}`（left=1 → 块 A 尾=2） | `left_max[3] = -3` | `{3}`（块 B 头=3 → right=3） | `{1,2,3}` | **3** |
| i = 2：`[2,4]` = `[-1,-3,5]` | `right_max[2] = -1` | `{2}`（left=2 → 块 A 尾=2） | `left_max[4] = 5` | `{3,4}`（块 B 头=3 → right=4） | `{2,3,4}` | **5** |
| i = 3：`[3,5]` = `[-3,5,3]` | `right_max[3] = 5` | `{3,4,5}`（left=3 → 块 A 尾=5） | `left_max[5] = 5` | `{3,4,5}`（块 A 头=3 → right=5） | `{3,4,5}` | **5** |
| i = 4：`[4,6]` = `[5,3,6]` | `right_max[4] = 5` | `{4,5}`（left=4 → 块 A 尾=5） | `left_max[6] = 6` | `{6}`（块 B 头=6 → right=6） | `{4,5,6}` | **6** |
| i = 5：`[5,7]` = `[3,6,7]` | `right_max[5] = 3` | `{5}`（left=5 → 块 A 尾=5） | `left_max[7] = 7` | `{6,7}`（块 B 头=6 → right=7） | `{5,6,7}` | **7** |

> 表中“块 A”指 `left` 所在的块，“块 B”指 `right` 所在的块。`i = 0` 和 `i = 3` 是窗口与块边界完全对齐的情况，`left`、`right` 同属一块（A = B），两个查表各自都覆盖了整个窗口，公式照样成立；其余窗口则是“A 块的后缀 + B 块的前缀”，并集恰好等于整个窗口。

最终输出：`[3, 3, 5, 5, 6, 7]`。

### 💻 Java 代码实现

```java
public class SolutionDP {
    public int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || nums.length == 0 || k <= 0) return new int[0];
        int n = nums.length;
        int[] res = new int[n - k + 1];

        int[] left_max = new int[n];  // 块内前缀最大值
        int[] right_max = new int[n]; // 块内后缀最大值

        // 1. 从左往右：计算块内前缀最大值，遇到块首重置
        for (int i = 0; i < n; i++) {
            if (i % k == 0) {
                left_max[i] = nums[i];
            } else {
                left_max[i] = Math.max(left_max[i - 1], nums[i]);
            }
        }

        // 2. 从右往左：计算块内后缀最大值，遇到块末重置
        for (int i = n - 1; i >= 0; i--) {
            if (i == n - 1 || (i + 1) % k == 0) {
                right_max[i] = nums[i];
            } else {
                right_max[i] = Math.max(right_max[i + 1], nums[i]);
            }
        }

        // 3. 查表：左半段看 right_max[left]，右半段看 left_max[right]
        for (int i = 0; i < res.length; i++) {
            int left = i;
            int right = i + k - 1;
            res[i] = Math.max(right_max[left], left_max[right]);
        }

        return res;
    }
}
```

### 复杂度

- 时间 $O(N)$：两个预处理循环各扫一遍，答案循环扫 `N - k + 1` 次，全是单层循环；
- 空间 $O(N)$：`left_max`、`right_max` 各占一个长度为 N 的数组。

## 📊 双战神解法终极横向对比

| 维度 | 🏃 战神解法一（单调队列法） | 🧱 战神解法二（分块双向 DP 法） |
| :--- | :--- | :--- |
| **底层核心思想** | 贪心思想、实时维护单调递减队列 | **动态规划（DP）**、子问题预处理与状态合并 |
| **时间复杂度** | **$O(N)$**（每个下标最多进出队列各 1 次） | **$O(N)$**（三个独立的单层 `for` 循环） |
| **空间复杂度** | **$O(K)$**（队列最多同时存 $K$ 个元素） | $O(N)$（需要开辟两个长度为 $N$ 的大坝数组） |
| **编码复杂度** | 较高（需熟练操作双端队列头尾指针） | 极低（三个极其机械、工整的单层循环） |
| **边界条件坑** | 容易搞错滑出窗口的下标过期逻辑 | 几乎无坑，只需注意 `% k == 0` 的边界筑基 |
| **工程实用度** | 内存开销小，适合运行内存极度受限场景 | 稳定性强，代码无嵌套分支，对 CPU 分支预测极度友好 |
