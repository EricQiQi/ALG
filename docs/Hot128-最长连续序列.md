# 算法笔记：最长连续序列（力扣 128 题）

## 题目描述
给定一个未排序的整数数组 `nums`，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。要求时间复杂度为 $O(n)$。

```
输入: nums = [100,4,200,1,3,2]
输出: 4
解释: 最长连续序列是 [1,2,3,4]，长度为 4
```

---

## 核心思想

> **HashSet 去重 + 只从"序列起点"开始数。**

排序能做到但那是 $O(n \log n)$，不满足要求。$O(n)$ 的关键在于**不做无用功**：

- 把所有数丢进 `HashSet`（顺便去重）；
- 对每个数 `num`，只有当 `num-1` **不在**集合里时，`num` 才是一段连续序列的**起点**；
- 从起点开始不断查 `num+1、num+2...` 往后数，统计长度。

**为什么是 O(n)**：每个数字最多被访问两次——外层 for 一次、内层 while 一次（只有起点才触发 while）。非起点直接被 `if` 跳过，不会重复数。

---

## 图解：起点判定

```
set = {100, 4, 200, 1, 3, 2}

num=100 → 99 不在 → 是起点 → 数：100（101 不在）→ 长度 1
num=4   → 3 在   → 不是起点 → 跳过
num=200 → 199 不在 → 是起点 → 数：200 → 长度 1
num=1   → 0 不在 → 是起点 → 数：1→2→3→4（5 不在）→ 长度 4 ✅
num=3   → 2 在   → 跳过
num=2   → 1 在   → 跳过

最大长度 = 4
```

只有 `1` 和 `100`、`200` 触发了往后数，`2/3/4` 都被"前一个数存在"挡掉了，避免重复计算。

---

## 代码实现 (Java)

```java
public int longestConsecutive(int[] nums) {
    if (nums == null || nums.length == 0) return 0;

    Set<Integer> set = new HashSet<>();
    for (int num : nums) set.add(num);   // 去重 + O(1) 查找

    int maxLen = 0;
    for (Integer num : set) {            // 注意：遍历 set 而非 nums（跳过重复值）
        if (!set.contains(num - 1)) {    // 只有起点才往后数
            int count = 1;
            int start = num;
            while (set.contains(start + 1)) {
                start++;
                count++;
            }
            maxLen = Math.max(maxLen, count);
        }
    }
    return maxLen;
}
```

---

## ❗关键易错点

**1. 外层要遍历 `set`，不是 `nums`**
若遍历 `nums`，重复元素（如 `[1,1,1,2]`）会触发多次相同的起点统计，虽然结果对但浪费时间。遍历 set 天然去重。

**2. 起点判定是 `!set.contains(num-1)`**
"我的前一个数不存在" = 我是这段序列的第一个。少了这个判断就退化成 $O(n^2)$。

**3. 空数组返回 0**
边界要单独处理。

---

## 复杂度分析

* **时间复杂度**：$O(n)$。每个元素最多被访问两次（外层一次、内层 while 一次）。
* **空间复杂度**：$O(n)$。HashSet 存储所有元素。

---

## 💡 记忆口诀

> **全丢进 Set 去个重，只从前一个不存在的起点往后数；每个数最多被摸两次，所以还是 O(n)。**
