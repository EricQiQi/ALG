# 算法笔记：编辑距离（力扣 72 题）

## 题目描述
给你两个字符串 `word1` 和 `word2`，返回把 `word1` 转换成 `word2` 所需的**最少操作数**。每次操作只能：

1. 插入一个字符
2. 删除一个字符
3. 替换一个字符

```
输入：word1 = "horse", word2 = "ros"
输出：3
解释：horse -> rorse（替换 h 为 r）-> rose（删除 r）-> ros（删除 e）

输入：word1 = "intention", word2 = "execution"
输出：5
解释：intention -> inention（删除 i）-> enention（替换 i 为 e）-> exention（替换 n 为 x）
     -> exection（替换 n 为 c）-> execution（插入 u）
```

> 📌 关键理解：和 1143 最长公共子序列同属**双串二维 DP**——状态照样是"两个前缀的匹配情况"，区别在于 LCS 求"免费配对最多几个字符"，本题求"配不上的字符最少花几步摆平"。操作没有顺序限制，但每一步只处理两个前缀的**末尾字符**，所以三种操作恰好对应 DP 表的三个来源方向。

---

## 解法：多维动态规划（双串二维 DP 表）

### 1. 核心思想
把「`word1` 前 i 个字符变成 `word2` 前 j 个字符的最少步数」定义为状态，按**两个当前字符是否相等**分类讨论。

* **状态定义**：`dp[i][j]` = `word1` 前 `i` 个字符转换成 `word2` 前 `j` 个字符的最少操作数。
* **状态转移**：比较 `word1[i-1]` 与 `word2[j-1]`：
  * **相等**：末尾字符天然配对，0 代价，直接继承左上角：
    $$dp[i][j] = dp[i-1][j-1]$$
  * **不等**：必须花 1 步操作摆平末尾字符，三种选择取最小：
    $$dp[i][j] = 1 + \min(dp[i][j-1],\ dp[i-1][j],\ dp[i-1][j-1])$$
    * `dp[i][j-1]`：**插入**——在 word1 末尾补一个 `word2[j-1]`，目标多出的字符被消掉；
    * `dp[i-1][j]`：**删除**——删掉 `word1[i-1]`，源多出的字符被消掉；
    * `dp[i-1][j-1]`：**替换**——把 `word1[i-1]` 改成 `word2[j-1]`，两字符强行配对。
* **边界（初始条件）**：`dp[i][0] = i`（word2 为空，只能全删除）、`dp[0][j] = j`（word1 为空，只能全插入）。与 LCS 全 0 边界不同，**必须显式初始化**。
* **返回**：`dp[m][n]`。

> 下标约定同 LCS：`dp` 开 `(m+1) x (n+1)`，第 0 行/列是"空前缀"哨兵，`dp[i][j]` 对应字符 `word1[i-1]`、`word2[j-1]`。

### 2. 代码实现 (Java)

```java
class Solution {
    public int minDistance(String word1, String word2) {
        int m = word1.length();
        int n = word2.length();
        int[][] dp = new int[m + 1][n + 1];  // dp[i][j]: word1 前i个 转成 word2 前j个 的最少步数

        for (int i = 0; i <= m; i++) dp[i][0] = i;  // 转成空串：全删除
        for (int j = 0; j <= n; j++) dp[0][j] = j;  // 空串转出：全插入

        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (word1.charAt(i - 1) == word2.charAt(j - 1)) {
                    // 当前字符配对成功，0 代价继承左上
                    dp[i][j] = dp[i - 1][j - 1];
                } else {
                    // 插(左)、删(上)、替(左上) 三选一，取最优 +1
                    dp[i][j] = 1 + Math.min(dp[i][j - 1], Math.min(dp[i - 1][j], dp[i - 1][j - 1]));
                }
            }
        }
        return dp[m][n];
    }
}
```

### 3. 复杂度分析
* **时间复杂度**：$O(m \times n)$。双重循环，每格 $O(1)$。
* **空间复杂度**：$O(m \times n)$。二维 DP 表。

### 4. 填表过程图解
以 `word1 = "horse"`（行）、`word2 = "ros"`（列）为例：

```text
        ""  r  o  s
     ""  0  1  2  3      ← 第0行/列 = 边界（全插入/全删除）
      h  1  1  2  3      ← h≠r：1+min(左1, 上1, 左上0) = 1（替换 h->r）
      o  2  2  1  2      ← o=o ✓ 直接继承左上"1"
      r  3  2  2  2      ← r=r ✓ 继承左上"2"
      s  4  3  3  2      ← s=s ✓ 继承左上"2"
      e  5  4  4  3      ← e≠s：1+min(左3, 上2, 上左2) = 3（删除/替换均可）
返回 dp[5][3] = 3
```

> 直观记忆：**相等抄左上，不等取「左、上、左上」最小 +1**——方向即操作：左=插入、上=删除、左上=替换。

---

## 💡 总结
编辑距离是**双串二维 DP 的"最小操作"版模板**：状态 `dp[i][j]` 表示前缀转换的最少步数，当前字符"相等抄左上，不等取左/上/左上最小值 +1"。它与 1143 LCS 结构几乎相同，差别只在两点：边界不是全 0 而是行列下标（空前缀转换必须付删除/插入代价），不等时除了上、左还要考虑左上（替换是 LCS 没有的操作）。

| 特性 | 说明 |
| :--- | :--- |
| **思维出发点** | 每步只处理两个前缀的末尾字符：配对（免费）或插/删/替（花 1 步）。 |
| **边界** | `dp[i][0]=i`、`dp[0][j]=j`，需显式初始化（与 LCS 全 0 边界不同）。 |
| **时间 / 空间** | $O(mn)$ / $O(mn)$。 |

> 🔧 相关变体：
> * **空间优化到 $O(n)$**：每格只依赖左、上、左上三格，可压一维滚动数组，但需临时变量保存"左上旧值"（同 LCS 的回溯优化难点）。
> * **只允许插入和删除**（无替换）：去掉左上分支、替换改为"删 + 插"两步即可，答案 = $m + n - 2 \times \text{LCS 长度}$——可见 LCS 正是"免费配对字符数"，两题互为镜像。
> * **判断编辑距离 ≤ 1**（力扣 161 题）：不必建表，找到第一处不匹配后检验剩余部分即可。

> ⚠️ 易错点：
> 1. **边界必须写成 `dp[i][0]=i`、`dp[0][j]=j`**——套用 LCS 的默认全 0 会漏掉"转成空串要 i 次删除"的代价，`"horse"/""` 会算出 0。
> 2. **`charAt(i-1)` 别写成 `charAt(i)`**——dp 下标比字符串多 1（第 0 行/列是空前缀），字符比较要回退一位。
> 3. **不等时三个来源都要参与 min**——漏掉左上 `dp[i-1][j-1]` 等于禁用替换，`"a"/"b"` 会算出 2 而不是 1。
> 4. **循环上界是 `i <= m`、`j <= n`**——dp 表多开一行一列，写成 `< m` 会算不到右下角。
> 5. **插入和删除的方向别搞反**——`dp[i][j-1]` 是插入（消目标字符）、`dp[i-1][j]` 是删除（消源字符）；好在两者都只 +1，取 min 时写反不影响结果，但理解转化路径时会出错。
