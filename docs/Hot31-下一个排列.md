# 算法笔记：下一个排列（力扣 31 题）

## 题目描述
把数组看成一个"号码"，把所有可能的排列按从小到大排成一队。给定当前号码，**原地**变成队伍里的下一个（恰好大一点的）。如果已经是最大的，就变回最小的。

```
输入：nums = [1,2,3]
输出：[1,3,2]

输入：nums = [3,2,1]
输出：[1,2,3]（321 已经是最大，翻回最小）

输入：nums = [1,1,5]
输出：[1,5,1]
```

> 📌 关键理解：像**里程表**。表从右往左看，右边只要是一段"从大到小"的数字，说明这几位已经滚到头了、再滚也变不了——想变大只能动它左边第一个"还没滚满"的位（记作 `i`）：把它换成一个**刚好大一点**的数，然后把后面的位**全部归零**（摆成最小）。

---

## 解法：三步走

### 1. 核心思想
要让号码"恰好大一点"，就三件事：**变的位置尽量靠右、变的幅度尽量小、变完后面摆到最小**。拆成三步：

* **第 1 步：从右往左，找第一个"比右边邻居小"的数**，位置记作 `i`。
  找不到（`i = -1`）说明整个表从大到小一字排开——已经是最大号码，跳到第 4 步。
* **第 2 步：再从最右往左，找第一个比 `nums[i]` 大的数**，位置记作 `j`。
  因为 `i` 右边那段是从大到小排的，所以"从最右遇到的第一个比它大的"恰好就是那段里**比 `nums[i]` 大的数中最小的**——换完刚好只大一点点。
* **第 3 步：把 `nums[i]` 和 `nums[j]` 交换**（这一位算"进了一格"）。
  换完 `i` 右边那段**依然是从大到小**（没被破坏，可以验证：`j` 右边的数都不比旧的 `nums[i]` 大，`j` 左边的数都不比旧的 `nums[j]` 小）。
* **第 4 步：把 `i` 后面的整段倒过来**（从大到小 → 从小到大，即这段能摆出的最小样子）。
  找不到 `i` 的情况（`i = -1`）也走这步：`i + 1 = 0`，正好把**整个数组**倒过来，最大直接变最小，翻篇从头开始。

### 2. 代码实现 (Java)

```java
class Solution {
    public void nextPermutation(int[] nums) {
        int n = nums.length;

        // 第 1 步：从右往左，找第一个"比右边小"的位置 i（一路都是"右边更小"就一路退，退到 -1 表示没找到）
        int i = n - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) i--;

        if (i >= 0) {
            // 第 2 步：从最右往左，第一个比 nums[i] 大的数 j（= 比 nums[i] 大的数里最小的）
            int j = n - 1;
            while (nums[j] <= nums[i]) j--;

            // 第 3 步：交换，i 这一位"进一格"
            swap(nums, i, j);
        }

        // 第 4 步：i 后面整段倒过来变成最小；i=-1 时就是从 0 开始整个倒过来
        reverse(nums, i + 1, n - 1);
    }
}
```

### 3. 追踪图解
以 `[2,3,1,5,4]` 为例：

```text
下标:      0  1  2  3  4
初始:  [2, 3, 1, 5, 4]
① 从右往左看：5≥4 没事，1<5 停   → i=2（值 1 是"没滚满"的位，右边 5,4 已到头）
② 再从最右看：4>1 即停           → j=4（4 是尾巴里比 1 大的数中最小的）
③ 1 和 4 交换                    → [2, 3, 4, 5, 1]
④ 把 i 后面 (5,1) 倒过来         → [2, 3, 4, 1, 5] ✓
（号码从 23154 变成 23415，恰好大一点）
```

### 4. ⭐ 重点：为什么光交换不行，必须把 i 后面倒过来

直觉误区：找到 i、找到 j，一交换完事——**不对，交换只是"进了一格"，后面的低位还没"归零"**。

还是 `[2,3,1,5,4]`，只交换不倒过来试试：

```text
只换不倒：  [2, 3, 4, 5, 1]  ✗

前三位定成 "234" 后，尾巴就剩 {1,5} 两个数，只有两种摆法：
     15  <  51
     ↑        ↑
   该摆这个   交换完恰好是从大到小的 51 = 尾巴能摆出的最大样子

放到数轴上看：
   23154 ──→ 23415 ──→ 23451
   原号码    ✓ 正解     ✗ 只换不倒落在这，中间跳过一个
```

里程表视角一句话：**"4" 那格往上滚了一格，下面两格必须立刻归零（从最小的 15 重新滚），得到的才是下一个号**。只进位不归零，等于低位还停在最大刻度上，自然跨过了中间号码。

为什么倒一下就行、不用真的排序：`i` 后面这段本来就是从大到小，第 2、3 步的换法不会破坏这一点，所以**倒过来**就是从小到大=最小，$O(n)$ 完事；真去排序会退化成 $O(n\log n)$。

### 5. 复杂度分析
* **时间复杂度**：$O(n)$。第 1、2 步各扫一遍，倒序至多 $n/2$ 次交换。
* **空间复杂度**：$O(1)$。原地操作。

---

## 💡 总结
这题不用算任何东西，全靠观察"号码"的结构：右边一段从大到小 = 已滚到头；第一个没排好的位 = 该进位的地方；从最右找到的第一个更大值 = 最小的进位幅度；把从大到小的一段倒过来 = 最便宜的"归零"。

> 🔑 记忆口诀：**从右找没排好的 i，右找刚好大的 j 一换，i 后面整个倒过来归最小**；全程从大到小就整个倒过来翻篇。（只换不归零就会跳过号码，见重点小节 4）

> 🔧 相关变体：
> * **上一个排列**：完全反过来——从右找第一个"比右边邻居**大**"的位，再从最右找第一个**比它小**的数交换，后面那段倒过来摆成最大。
> * **循环生成全部排列**：从最小的排列出发反复调用本算法，能把 n 个数的所有排列按顺序一个个列出来，直到号码翻回最小为止（C++ 的 `next_permutation` 就靠返回值告诉你翻没翻篇），可以替代回溯法"枚举排列"的写法。
> * **C++ 标准库对照**：`next_permutation(begin, end)` 和本算法完全等价；Java 没有内置，手写本题是面试高频。

> ⚠️ 易错点：
> 1. **两个 while 的跳过条件都带等号**（`nums[i] >= nums[i+1]` 跳、`nums[j] <= nums[i]` 跳）：第 1 步丢等号会停在两个相邻相等的数上（它们其实没"变大空间"），第 2 步丢等号可能挑到一个跟 `nums[i]` 相等的数，换了等于没换。带等号还顺手兼容了重复数字（`[1,1,5]` 用例）。
> 2. **`reverse(nums, i + 1, ...)` 必须写在 if 外面**——`i = -1`（最大号码）时 `i+1` 正好是 0，整个数组倒过来翻篇；写进 if 里，`[3,2,1]` 会原样输出而不是 `[1,2,3]`。
> 3. **第 2 步必须从最右往左扫**——从大到小的尾巴里，"最靠右的那个比 `nums[i]` 大的数"才是"比它大的数里最小的"；从左往右找会撞上更大的，结果直接跳过中间好几个号码。
> 4. **第 4 步是倒过来不是排序**——前面说过这段必然是从大到小，倒过来就是最小；真调排序既慢又说明没看懂结构。
> 5. **`i` 左边的数字一个都别动**——变大的动作全发生在 `i` 和它右边，左边保持原样才叫"恰好大一点"。
