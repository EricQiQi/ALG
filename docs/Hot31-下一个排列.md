# 算法笔记：下一个排列（力扣 31 题）

## 题目描述
给定一个数字排列 `nums`，求出其**下一个字典序更大**的排列——即把数组重新排列成"恰好比当前排列大的下一个排列"。如果已经是最大排列，则重排为**最小排列**（从头循环）。必须原地修改，只允许使用额外常数空间。

```
输入：nums = [1,2,3]
输出：[1,3,2]

输入：nums = [3,2,1]
输出：[1,2,3]（321 已是最大，回绕到最小）

输入：nums = [1,1,5]
输出：[1,5,1]
```

> 📌 关键理解：把排列想成**里程表**——从右往左看，一段"降序尾巴"意味着这一段已经滚到了它能表示的最大值，要"进位"就得动它左边第一个还没滚满的数字（**枢轴**）：找一个刚好比它大的数换上来（进位一步），再把尾巴复位到最小（归零）。"恰好大一点"对应进位只 +1，"尾巴最小"对应低位全部归零。

---

## 解法：三步走（找升点 → 找后继 → 翻转后缀）

### 1. 核心思想
字典序比较看**最左边的差异位**，所以要让"变大"发生得尽量靠右、幅度尽量小：

* **第 1 步（找枢轴 i）**：从右往左找第一个**严格上升点** `nums[i] < nums[i+1]`。`i` 右边的后缀全程 `≥` 下降，已是该段的最大排列，进位必须发生在 `i`。
* **第 2 步（找后继 j）**：在降序后缀里**从右往左**找第一个 `nums[j] > nums[i]`。后缀降序 ⟹ 从右扫先遇到的那个"比枢轴大的数"恰是后缀中**比 nums[i] 大的最小者**——进位幅度刚好 +1。
* **第 3 步（交换 + 翻转）**：交换 `nums[i]`、`nums[j]` 后后缀**仍保持降序**（可证：`j` 右侧的数都 `≤` 旧 `nums[i]`，`j` 左侧的数都 `≥` 旧 `nums[j]` > 旧 `nums[i]`），把后缀**翻转**成升序即复位为最小。高位段完全不动。

* **特例**：整个数组降序（找不到升点，`i = -1`）→ 已是最大排列，跳过交换、`reverse(0, n-1)` 直接回绕到最小。代码里 `reverse(nums, i + 1, n - 1)` 中 `i + 1 = 0` 天然覆盖此情况。

### 2. 代码实现 (Java)

```java
class Solution {
    public void nextPermutation(int[] nums) {
        int n = nums.length;

        // 第 1 步：从右往左，找第一个下降点 i（后缀全程 >= 时 i 一路退到 -1）
        int i = n - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) i--;

        if (i >= 0) {
            // 第 2 步：降序后缀里从右往左第一个 > nums[i] 的数 = 比枢轴大的最小者
            int j = n - 1;
            while (nums[j] <= nums[i]) j--;

            // 第 3 步：进位——枢轴位换成后继值
            swap(nums, i, j);
        }

        // 尾巴复位：后缀本是降序，翻转即升序（最小）；i=-1 时整段翻转回绕
        reverse(nums, i + 1, n - 1);
    }
}
```

### 3. 追踪图解
以 `[2,3,1,5,4]` 为例：

```text
下标:      0  1  2  3  4
初始:  [2, 3, 1, 5, 4]
① 找升点: 5≥4 跳过，1<5 停      → 枢轴 i=2（值 1），后缀 [5,4] 已滚满
② 找后继: 从右看 4>1 即停       → j=4（值 4 是后缀里比 1 大的最小者）
③ 交换:   [2, 3, 4, 5, 1]       ← 进位：1 → 4
④ 翻转后缀 [3..4]:              → [2, 3, 4, 1, 5] ✓ 尾巴 5,1 归零成 1,5
（字典序：23154 → 23415，恰好大一点）
```

### 4. 复杂度分析
* **时间复杂度**：$O(n)$。三步各自至多扫一遍数组，翻转至多 $n/2$ 次交换。
* **空间复杂度**：$O(1)$。原地操作。

## 💡 总结
下一个排列是**字典序结构的利用题**：模板题里没有"计算"，只有对排列结构的观察——降序后缀=已最大化、升点=该进位的位置、从右找到的第一个更大值=最小进位量、翻转=降序段复位升序的最廉价方式（不需要真的排序）。四个细节合成一句话：**找升点、找后继、交换、翻转后缀**。

> 🔑 记忆口诀：**升点进位、后继加一、翻转尾巴归最小**；整串降序则翻转回绕。

> 🔧 相关变体：
> * **上一个排列**：对称操作——从右找第一个**下降**点（`nums[i] > nums[i+1]`），后缀里从右找第一个**小于**它的数交换，再翻转升序后缀。
> * **循环生成全排列**：从升序数组出发反复调用本算法直到回绕，即可按字典序产出全部 $n!$ 个排列（C++ `std::next_permutation` 的惯用法，返回值 = 是否未回绕），可替代部分回溯题的"枚举排列"写法。
> * **C++ 标准库对照**：`next_permutation(begin, end)` 与本算法完全等价；Java 无内置，手写本题是面试高频。

> ⚠️ 易错点：
> 1. **两处跳过条件都不能丢等号：第 1 步 `>=` 跳、第 2 步 `<=` 跳**——升点要求严格升高、后继要求严格更大；丢等号则第 1 步会停在相邻相等值上选到假枢轴、第 2 步可能和等于枢轴的值做无效交换（排列不变）；带等号的写法同时兼容重复元素（`[1,1,5]` 用例）。
> 2. **`reverse(nums, i + 1, ...)` 必须留在 if 外面**——`i = -1`（最大排列）时 `i+1 = 0` 恰好整段翻转完成回绕；把翻转塞进 `if` 里，`[3,2,1]` 会原样输出而不是 `[1,2,3]`。
> 3. **j 要从最右往左扫**——降序后缀里"最靠右的 > nums[i]"才等于"比 nums[i] 大的最小者"；从左往右找会撞上更大的值，得到跳过了一个排列的错误答案。
> 4. **第 3 步是翻转不是排序**——交换后后缀天然保持降序（第 2 步的选取保证了这一点），翻转 $O(n)$ 即可；真调排序会退化到 $O(n\log n)$ 且掩盖了对结构的理解。
> 5. **高位段一个字节都别动**——进位只影响 `i` 及其右边；这是"恰好大一点"的定义所在。
