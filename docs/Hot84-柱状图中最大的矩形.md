# LeetCode 84. 柱状图中最大的矩形

对应源码：[Hot84_largestRectangleArea.java](../src/s12_stack/Hot84_largestRectangleArea.java)

## 题目描述

给定 `n` 个非负整数，用来表示柱状图中各个柱子的高度。每个柱子彼此相邻，且宽度为 1。求在该柱状图中，能够勾勒出来的矩形的最大面积。

```
[2,1,5,6,2,3] → 10        （高度 5、6 两根柱子，5 × 2 = 10）
[2,4]         → 4
```

## 💡 大白话解析

**枚举每根柱子，把它当作矩形的高度**，那么矩形能向两侧扩展到哪里？

> 左边第一根**比它矮**的柱子之前，右边第一根**比它矮**的柱子之前。

因为一旦遇到更矮的柱子，这个高度的矩形就撑不过去了。于是：

```
面积 = heights[i] × (右边界 - 左边界 - 1)
```

这正是「找左右两侧第一个更小元素」——单调栈的信号（和 [每日温度](Hot739-每日温度.md) 同源，那题找更大、这题找更小）。

**最关键的一步认知转变：不是在入栈时结算，而是在出栈时结算。**

一个下标被弹出的瞬间，它的左右边界**同时确定**了：

| 边界 | 是谁 | 为什么 |
| :--- | :--- | :--- |
| 右边界 | 当前 `i` | 正是它比栈顶矮，才触发了这次弹出 |
| 左边界 | **弹出后**的新栈顶 | 栈内递增，所以下面那个就是左侧第一个更矮的 |

一次弹栈拿到两个边界，所以整体 O(n)。

顺带就明白了栈为什么是**递增**的：只有当前柱子比栈顶**矮**才弹，能留在栈里的自然从底到顶越来越高。

## 图解

`heights = [2,1,5,6,2,3]`，最大矩形（▓）= 高度 5 × 宽度 2：

```
        i= 0  1  2  3  4  5
   h=6       .  .  .  █  .  .
   h=5       .  .  ▓  ▓  .  .
   h=4       .  .  ▓  ▓  .  .
   h=3       .  .  ▓  ▓  .  █
   h=2       █  .  ▓  ▓  █  █
   h=1       █  █  ▓  ▓  █  █
```

这个矩形是在 `i=5`（高度 2）时被算出来的：

```
i=5 到来，栈内（底→顶）为 [0, 2, 3, 4]，对应高度 0*, 1, 5, 6   （*方法一的左哨兵）

  弹出 4（高 6）：右边界 = 5，左边界 = 新栈顶 3 → 宽 = 5-3-1 = 1 → 面积 6×1 = 6
  弹出 3（高 5）：右边界 = 5，左边界 = 新栈顶 2 → 宽 = 5-2-1 = 2 → 面积 5×2 = 10 ★
  栈顶 2（高 1）不再比 2 矮 → 停止弹出，i=5 入栈
```

**注意「弹出后」三个字**：算高度 5 那根柱子时，左边界是 `3` 被弹走之后露出来的 `2`，不是 `3`。

## 哨兵：为什么需要它

不用哨兵的话，有两个边界情况要单独处理：

1. 栈被弹空 → 说明左边没有更矮的柱子，左边界应该是 `-1`
2. 遍历结束栈里还有剩余 → 它们的右边界是 `n`，需要再补一个收尾循环

两个方法用不同方式消掉这两个特判：

| | 方法一：真哨兵 | 方法二：虚拟哨兵 |
| :--- | :--- | :--- |
| 左边界 | 数组头部补一个 `0`，栈底永远是它，`peek()` 不会空 | `stack.isEmpty() ? -1 : stack.peek()` |
| 右边界 | 数组尾部补一个 `0`，遍历到它时把剩余柱子全部弹出结算 | 循环多走一格 `i <= n`，用 `currentHeight = 0` 模拟 |
| 代价 | 多开一个长度 `n+2` 的数组 | 循环里要判 `i == n`，入栈要判 `i < n` |

方法一的哨兵为什么能保证栈不空？因为 `newHeights[0] = 0` 而所有高度都 `≥ 0`，弹出条件 `newHeights[i] < newHeights[栈顶]` 在栈顶是下标 0 时变成 `< 0`，**永不成立**——所以下标 0 这根哨兵柱子永远不会被弹出。

### 左哨兵必须入栈，右哨兵不必

两个哨兵的**职责根本不同**，这是最容易混淆的地方：

| | 职责 | 需要真的在栈里吗 |
| :--- | :--- | :--- |
| **左哨兵** | 被 `peek()` **读出来当左边界** | ✅ 必须。方法一让下标 0 钉在栈底；方法二没有实体，用 `-1` 代替 |
| **右哨兵** | 只负责**触发结算**（把剩余柱子全弹光） | ❌ 不必。它在 `while` 条件里起效，弹完就没用了 |

实测 `[2,1,5,6,2,3]` 最后一轮的轨迹，能直接看出这一点：

```
i = 6（== n，currentHeight = 0）：
    弹出下标 5（高 3）  左边界 = 4   宽 = 1  面积 = 3
    弹出下标 4（高 2）  左边界 = 1   宽 = 4  面积 = 8
    弹出下标 1（高 1）  左边界 = -1  宽 = 6  面积 = 6
    ↑ 哨兵的活全在 while 里干完了，此刻栈已空
```

右哨兵从头到尾**没有充当过任何柱子的左边界**（那个 `-1` 是 `isEmpty()` 兜底给出的，不是栈里的元素）。所以方法二里用 `if (i < n)` 跳过最后一轮的入栈，不影响任何结果——实测 14 组固定用例 + 50000 组随机用例，与暴力解三方对拍全部一致。

> 方法一在 `i = n+1` 时也把右哨兵 push 进了栈，同样是死代码，只不过它是个合法下标，看着不刺眼。

**一句话记法：左哨兵要当边界，得在栈里；右哨兵只管触发结算，用完即弃。**

## 💻 Java 代码实现

### 方法一：真哨兵（首尾各补一个 0）

```java
public int largestRectangleArea_1(int[] heights) {
    int n = heights.length;
    int[] newHeights = new int[n + 2];
    newHeights[0] = 0;          // 左哨兵：保证栈永不为空
    newHeights[n + 1] = 0;      // 右哨兵：保证剩余柱子全被结算
    System.arraycopy(heights, 0, newHeights, 1, n);

    int maxArea = 0;
    Deque<Integer> stack = new ArrayDeque<>();   // 单调递增栈，存下标

    for (int i = 0; i < newHeights.length; i++) {
        while (!stack.isEmpty() && newHeights[i] < newHeights[stack.peek()]) {
            int h = newHeights[stack.pop()];     // 被弹出的柱子高度
            int leftBoundary = stack.peek();     // 弹出后的新栈顶 = 左侧第一个更矮
            int width = i - leftBoundary - 1;    // 开区间宽度
            maxArea = Math.max(maxArea, h * width);
        }
        stack.push(i);
    }
    return maxArea;
}
```

### 方法二：虚拟哨兵（不复制数组）

```java
public int largestRectangleArea_2(int[] heights) {
    int n = heights.length;
    Deque<Integer> stack = new ArrayDeque<>();
    int maxArea = 0;

    for (int i = 0; i <= n; i++) {              // 多走一格，i == n 时充当右哨兵
        int currentHeight = i == n ? 0 : heights[i];

        while (!stack.isEmpty() && currentHeight < heights[stack.peek()]) {
            int h = heights[stack.pop()];
            int leftBoundary = stack.isEmpty() ? -1 : stack.peek();   // 栈空则左边界 -1
            int width = i - leftBoundary - 1;
            maxArea = Math.max(maxArea, width * h);
        }
        if (i < n) stack.push(i);   // 右哨兵不入栈：它只负责触发结算
    }
    return maxArea;
}
```

## 复杂度分析

| 指标 | 复杂度 | 说明 |
| :--- | :---: | :--- |
| 时间 | O(n) | 每个下标进栈、出栈各至多一次；方法一额外一次 `arraycopy` 也是 O(n) |
| 空间 | O(n) | 栈最坏存 n 个下标（高度严格递增时）；方法一多一个 `n+2` 的数组 |

## ⚠️ 易错点

### 1. 宽度是 `i - leftBoundary - 1`，两个减一都不能少

左右边界都是「第一个**更矮**的柱子」，它们本身不属于矩形，是**开区间**。以 `[2,1,5,6,2,3]` 算高度 5 那根为例：左边界 2、右边界 5，实际覆盖下标 3、4 两根 → 宽 = 5-2-1 = 2。写成 `i - leftBoundary` 会多算一根。

### 2. 在**出栈时**结算，不是入栈时

入栈那一刻右边界还没出现，根本算不出宽度。所有"找到边界就结算"的单调栈题都是这个节奏。

### 3. 先 `pop()` 拿高度，再 `peek()` 拿左边界

```java
int h = newHeights[stack.pop()];    // 先弹
int leftBoundary = stack.peek();    // 再看新栈顶
```

顺序颠倒（先 peek 再 pop）会把自己当成左边界，宽度恒为 `i - 自己 - 1`，全错。

### 4. 方法一的 `stack.peek()` 没判空，靠的是哨兵

左哨兵 `0` 永远不会被弹出，所以 `while` 内部栈必然非空。**一旦去掉哨兵就必须像方法二那样判 `isEmpty()`**，否则弹到最后一个元素时 `peek()` 返回 `null`，拆箱 NPE。

### 5. `if (i < n) stack.push(i)`：右哨兵不要入栈

方法二最后一轮 `i == n` 时，`n` 是 `heights` 的**越界下标**。若无条件 `stack.push(i)`，它会被压进栈——循环随即结束、没人再读它，所以**结果仍然正确**（已对拍验证）；但一旦日后在循环外拿栈里的下标去索引 `heights`，就是 `ArrayIndexOutOfBoundsException`。

加了 `if (i < n)` **不会把哨兵弄没**：右哨兵是 `currentHeight = 0` 这个临时变量，它的活全在 `while` 里干完，本来就不需要进栈。完整辨析见上文「哨兵」一节的**左哨兵必须入栈，右哨兵不必**。

### 6. 用严格 `<`，等高柱子不弹

`[2,2,2]` 这类等高输入，靠**最后被弹出的那根**去计算完整宽度：前两根弹出时宽度偏小，但最后一根的左边界会退到 `-1`，拿到完整的 3，面积 6 正确。实测 `[2,2,2] → 6`、`[1,1,1,1] → 4`、`[0,1,0,1,0] → 1`、空数组 `→ 0`，均与暴力解一致。

## 🧠 单调栈通用骨架

和 [每日温度](Hot739-每日温度.md) 放在一起看，套路完全一样：

```java
for (int i = 0; i <= n; i++) {
    while (!stack.isEmpty() && 触发条件(当前元素, 栈顶元素)) {
        int idx = stack.pop();
        // 此刻三个量齐全：idx（自己）、i（右边界）、stack.peek()（左边界）
        结算答案;
    }
    stack.push(i);
}
```

| 题目 | 找什么 | 栈的单调性 | 结算的东西 |
| :--- | :--- | :---: | :--- |
| 739 每日温度 | 右边第一个**更大** | 递减 | 天数差 `i - idx` |
| 84 柱状图最大矩形 | 左右第一个**更小** | 递增 | 宽度 `i - 左 - 1` × 高度 |
| 42 接雨水 | 左右第一个**更大** | 递减 | 按层接水 `宽 × 高度差` |
| 496 下一个更大元素 | 右边第一个更大 | 递减 | 值本身 |

**记法**：求「更大」用递减栈，求「更小」用递增栈；栈的单调性和要找的方向**相反**——因为栈里存的是"还没等到答案的候选"，它们必须按等待的顺序排好。

## 🧠 记忆口诀

> **递增栈，出栈结算：右边界是当前 `i`，左边界是弹出后的新栈顶，宽度 = 右 - 左 - 1。**
>
> **首尾各垫一个 0：左边垫 0 免判空，右边垫 0 免收尾。**
>
> **左哨兵当边界，钉在栈底；右哨兵只触发结算，用完即弃。**
