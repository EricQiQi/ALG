# 相交链表（Intersection of Two Linked Lists）

## 题目描述

编写一个程序，找到两个单链表的**交点**。

示例：
```
listA: 1 → 2 ↘
              3 → 4 → 5
listB: 9 → 10 ↗

输出：交点为值为 3 的节点
```

> 约束：函数返回结果后，链表必须保持其原始结构；程序尽量满足 O(n) 时间复杂度，仅使用 O(1) 内存。

---

## 核心概念：什么是"相交"？（本题最重要的认知）

### ⚠️ 相交 = 共享同一段内存，不是"值相同"

两条链表相交后，从交点开始**共享同一批节点对象**：

```
listA: 1 → 2 ↘
              3 → 4 → 5     ← 这三个节点在内存中只有一份
listB: 9 → 10 ↗               listA 和 listB 都指向它们
```

为什么一旦相交就不会再分开？因为**每个节点只有一个 `next` 指针**，从交点开始后面只能走同一条路。

### 由此推出的关键性质

> **如果两条链表相交，它们的尾部必然完全一致（连长度都相同）。**

这正是"长链表先走几步对齐"解法的理论依据。

---

## ⭐ 易错点：为什么用 `tempA == tempB` 而不是比较 val？

### 正确写法

```java
if (tempA == tempB) {   // ✅ 比较引用（内存地址）
    return tempA;
}
```

Java 中对象变量存的是**引用（地址）**，`==` 比较的是两个引用是否指向**同一个对象**——这恰好就是"是否同一个节点"的严格判断。

### 错误写法

```java
if (tempA.val == tempB.val && tempA.next == tempB.next) {   // ❌
    return tempA;
}
```

**问题：误判"假相交"**

```
listA: 1 → 2 → null
listB: 9 → 2 → null
```

两条链表**完全没有相交**，但走到第二个节点时：
- `tempA.val == tempB.val`：2 == 2 ✅ 成立
- `tempA.next == tempB.next`：null == null ✅ 成立

条件成立 → 误判相交，返回错误结果！但实际上这是两个**值巧合相同的不同节点**。

### 一句话总结

> **值相等 ≠ 同一个节点。`==` 比的是内存地址，才是"是否同一对象"的准确判断。**

### 对比表

| 写法 | 比较内容 | 判断结果 |
|------|----------|----------|
| `tempA == tempB` | 内存地址是否相同 | 是否**同一个节点**（题目要的） |
| `tempA.val == tempB.val` | 值是否相同 | 是否**长得一样**（题目不要的） |

### 什么时候才比 val？

如果题目改成"找到第一个**值相同**的节点"，才需要比较 `val`。LeetCode 160 明确定义交点是 "same node object"（同一引用），所以必须比引用。

---

## 解法：长度差对齐 + 同步前进

### 算法步骤

1. **分别遍历**两条链表，求出各自长度 `lenA`、`lenB`
2. **长链表先走** `|lenA - lenB|` 步，让两个指针对齐到"距离尾部相同"的位置
3. **同速前进**，第一次 `tempA == tempB`（同一地址）的节点就是交点
4. 走到 `null` 都没相遇 → 不相交

### 图解执行过程

```
listA 长度 5: 1 → 2 → 3 → 4 → 5
listB 长度 3: 9 → 10 → 4（这里假设交点在 4，仅示意）

gap = 5 - 3 = 2，tempA 先走 2 步：
tempA:         3 → 4 → 5
tempB: 9 → 10 → 4

同步前进，在交点相遇 ✅
```

### 代码实现

```java
public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
    ListNode tempA = headA;
    ListNode tempB = headB;

    // 1. 求两条链表的长度
    int lenA = 0;
    while (tempA != null) {
        lenA++;
        tempA = tempA.next;
    }
    int lenB = 0;
    while (tempB != null) {
        lenB++;
        tempB = tempB.next;
    }

    // 2. 长链表先走 gap 步，对齐尾部
    int gap = Math.abs(lenA - lenB);
    tempA = headA;
    tempB = headB;
    if (lenA > lenB) {
        for (int i = 0; i < gap; i++) {
            tempA = tempA.next;
        }
    } else if (lenA < lenB) {
        for (int i = 0; i < gap; i++) {
            tempB = tempB.next;
        }
    }

    // 3. 同速前进，地址相同即为交点
    while (tempA != null) {
        if (tempA == tempB) {
            return tempA;
        }
        tempA = tempA.next;
        tempB = tempB.next;
    }

    return null;
}
```

### 复杂度

| 类型 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(m + n) | 两条链表各遍历两遍 |
| 空间 | O(1) | 只用了几个指针变量 |

## 拓展：双指针拼接法（更浪漫的解法）

还有一种不需要计算长度的写法：**指针 A 走完自己的链表后跳到 headB 继续走，指针 B 走完后跳到 headA 继续走**。

```
tempA 走的路程: listA → listB
tempB 走的路程: listB → listA

两条路径总长度相等：lenA + lenB = lenB + lenA
→ 两个指针必然在同一时刻到达交点（或同时到达 null）
```

```java
public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
    ListNode tempA = headA;
    ListNode tempB = headB;
    while (tempA != tempB) {           // 不相交时两者同时为 null，退出
        tempA = (tempA == null) ? headB : tempA.next;
        tempB = (tempB == null) ? headA : tempB.next;
    }
    return tempA;
}
```

> **一句话理解**：你走过来我的路，我走过去你的路，我们终会在交点相遇；如果注定无缘（不相交），也会在 null 处一起停下。

###核心原理图解
```text
                                null，跳到链表B
                                  ↓
链表A遍历路径：a1→a2→a3→c1→c2→c3→ null →  b1   →b2→b3→b4→c1
链表B遍历路径：b1→b2→b3→b4→c1→c2→ c3   →  null →a1→a2→a3→c1
                                          ↑              ↑
                                       null，跳到链表A   ↑
                                                     在此处相遇！
```

### 两种解法对比

| 维度 | 长度差对齐 | 双指针拼接 |
|------|-----------|-----------|
| 时间 | O(m + n) | O(m + n) |
| 空间 | O(1) | O(1) |
| 代码量 | 较长 | 极短 |
| 思路直观度 | 直观（先对齐再比较） | 巧妙（路程相等） |

## 易错点

1. **用 `val` 比较代替引用比较**：值相同不代表同一个节点，会误判"假相交"（详见上文重点章节）
2. **⭐ 统计长度后忘记重置指针**：`tempA`、`tempB` 在第一趟统计长度时已经走到 `null`，直接拿来对齐会对着 `null` 调 `.next` 报 NPE。第二趟遍历前必须重置：`tempA = headA; tempB = headB;`
3. **⭐ 双指针拼接法跳头时写成 `tempB` 而不是 `headB`**：走完一条链表要跳到**另一条链表的头节点**，必须写 `headB`，写成 `tempB` 会把 `null` 赋给自己，永远跳不出去。详见下方小节
4. **长度差对齐时移动错指针**：是**长**的链表先走，别移成短的
5. **忘记链表相交后尾部完全一致**：理解了这一点，才能理解为什么对齐后同速前进必然相遇

### ⭐ 为什么"指针重置"容易遗漏？

```java
// 第一趟：统计长度（此时 tempA/tempB 已经走到尾部 null）
while (tempA != null) {
    lenA++;
    tempA = tempA.next;
}

// ❌ 如果直接在这里开始对齐：
//    for (int i = 0; i < gap; i++) tempA = tempA.next;
//    tempA 已经是 null，tempA.next 直接 NPE！

// ✅ 必须先重置回起点：
tempA = headA;
tempB = headB;
```

**遗漏原因**：指针声明、长度统计、第二次遍历三段代码往往相距较远，写完统计循环后容易忘了指针已经"用废"（走到 `null` 了）。

**通用原则**：任何"一个指针跑两趟"的写法（先统计再查找），两趟之间必须显式重置回起点。更稳妥的风格是第一趟用独立的临时指针，第二趟重新从 `head` 出发。

### ⭐ 双指针拼接法：为什么是 headB 不能写成 tempB？

```java
while (tempA != tempB) {
    tempA = (tempA == null) ? headB : tempA.next;   // ✅ 跳另一条链表的头
    tempB = (tempB == null) ? headA : tempB.next;
}
```

**写错的情况：**

```java
tempA = (tempA == null) ? tempB : tempA.next;   // ❌
```

当 `tempA` 走到 `null` 时，此时 `tempB` 往往也已经是 `null`（或即将走到），把 `tempB` 赋给 `tempA` 相当于把 `null` 塞给自己：

- 两条链表**不相交**时，`tempB` 已经同步走到 `null`，`tempA` 被赋成 `null`，两个指针永远停在 `null` 上反复横跳 → **死循环**
- 两条链表**相交**时，`tempB` 还没到 `null` 也大概率处在错误位置，后续路径被打乱，根本找不到交点

**原因**：`headB` 是**固定不变的头节点引用**，`tempB` 是**会移动的游标**。跳头要的是"回到另一条链表的起点"这个固定位置，所以必须用 `headB`。

> 一句话：`headB` 是家的地址，`tempB` 是当前的位置。走完自己的路，要去的是对方家（`headB`），不是对方此刻站的地方（`tempB`）。
