# 算法笔记：最长上升子序列（力扣 300 题）

## 题目描述
给你一个整数数组 `nums` ，找到其中**最长严格递增子序列**的长度。

**子序列**：由数组派生、删除（或不删除）部分元素而不改变其余元素**相对顺序**得到的序列（不要求连续）。

```
输入：nums = [10,9,2,5,3,7,101,18]
输出：4
解释：最长递增子序列是 [2,3,7,101]（或 [2,5,7,101] 等），长度为 4。

输入：nums = [7,7,7,7]
输出：1
解释：要求严格递增，重复元素不能接龙，最长为 1。
```

> 📌 关键理解：与「子数组」要求连续不同，**子序列可以不连续、但相对顺序不能变**，且本题要求**严格递增**（相等不算）。这是经典的「以谁结尾」型 DP。

---

## 解法一：动态规划（以 i 结尾）

### 1. 核心思想
定义状态：`dp[i]` 表示**以 `nums[i]` 结尾**的最长递增子序列长度。
* **状态转移**：枚举 `i` 之前的每个 `j`（`j < i`），若 `nums[i] > nums[j]`，说明 `nums[i]` 能接在以 `nums[j]` 结尾的递增序列后面，长度 +1：
  $$dp[i] = \max_{\substack{j < i \\ nums[j] < nums[i]}}\big(dp[j] + 1\big)$$
* **边界（初始化）**：每个元素**自身**就是长度为 1 的递增子序列，故 `dp[i]` 全部初始化为 `1`。
* **返回**：`max(dp)`——LIS **不一定以最后一个元素结尾**，需用一个 `res` 单独跟踪全局最大值。

> 状态必须带「以 i 结尾」这个限定，否则无法判断 `nums[i]` 能否接在后面。这正是它与「打家劫舍/爬楼梯」（只问前 i 个最优）的关键区别。

### 2. 代码实现 (Java)

```java
class Solution {
    public int lengthOfLIS(int[] nums) {
        int n = nums.length;
        if (n <= 1) return n; // 空数组或单元素，答案即长度本身

        // dp[i]：以 nums[i] 结尾的 LIS 长度
        int[] dp = new int[n];
        Arrays.fill(dp, 1); // 每个元素自身构成长度为 1 的子序列

        int res = 1; // 全局最长（LIS 不一定以最后元素结尾，需单独跟踪）
        for (int i = 1; i < n; i++) {
            // 枚举 i 之前的每个 j，看 nums[i] 能否接在 nums[j] 后面
            for (int j = 0; j < i; j++) {
                if (nums[i] > nums[j]) { // 能接：长度 = dp[j] + 1，取最大
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            res = Math.max(res, dp[i]); // 打擂台更新全局最长
        }
        return res;
    }
}
```

### 3. 复杂度分析
* **时间复杂度**：$O(n^2)$。外层 $n$、内层平均 $n/2$ 的双重循环。
* **空间复杂度**：$O(n)$。开了长度为 `n` 的 DP 数组。

> 进阶：可用「贪心 + 二分」优化到 $O(n \log n)$，见解法二。本题数据量下 $O(n^2)$ 已够用。

### 4. 递推过程图解
以 `nums = [10,9,2,5,3,7,101,18]` 为例：

```text
i   nums[i]   能接的 j（nums[j]<nums[i]）        dp[i]
0    10        ——                                1
1     9        无（9<10 不成立）                   1
2     2        无                                1
3     5        j=2(2)                            dp[2]+1 = 2
4     3        j=2(2)                            dp[2]+1 = 2
5     7        j=2(2),3(5),4(3)                  max(dp[2],dp[3],dp[4])+1 = 3
6    101       j=0..5 全部                       max(...)+1 = dp[5]+1 = 4
7    18        j=2,3,4,5                         max(...)+1 = dp[5]+1 = 4
res = max(dp) = 4
```

> 注意：`dp[6]` 和 `dp[7]` 都是 4，但结尾不同（`101` 和 `18`）。所以**答案是 `max(dp)` 而非 `dp[n-1]`**——这里恰好 `dp[n-1]=4`，但若把 18 换成 5，`dp[n-1]` 就变小而答案不变。

## 解法二：贪心 + 二分（$O(n \log n)$）

### 1. 核心思想
维护一个数组 `tails`，令 **`tails[k]` = 长度为 `k+1` 的递增子序列的「最小末尾元素」**。`tails` 本身**始终严格递增**。
* 对每个 `num`，在 `tails` 有效区 `[0, size)` 里**二分**找**第一个 `>= num`** 的位置 `left`（lower_bound）。
  * 若 `left == size`（`num` 比所有末尾都大）：直接接长一档，`size++`。
  * 否则 `tails[left] = num`：把长度为 `left+1` 的序列末尾**压得更小**。
* `size`（有效元素个数）就是 LIS 长度。

> 贪心点：**末尾越小，后续能接的元素越多**，越有机会延伸出更长序列。所以遇到更小的 `num` 就替换掉同等长度序列的末尾，为后面「留空间」。

### 2. 代码实现 (Java)

```java
class Solution {
    public int lengthOfLIS(int[] nums) {
        // tails 始终严格递增；有效部分是前 size 个
        int[] tails = new int[nums.length];
        int size = 0; // 当前 LIS 长度

        for (int num : nums) {
            // 在 tails[0..size-1] 二分找第一个 >= num 的位置 left（lower_bound）
            int left = 0, right = size;
            while (left < right) {
                int mid = left + (right - left) / 2;
                if (tails[mid] < num) {
                    left = mid + 1; // 比 num 小：答案在右半
                } else {
                    right = mid; // >= num：可能是答案，往左继续夹
                }
            }

            tails[left] = num;        // 替换/写入：让长度为 left+1 的序列末尾尽可能小
            if (left == size) size++; // num 比所有末尾都大：接长一档
        }
        return size; // size 即 LIS 长度
    }
}
```

### 3. 复杂度分析
* **时间复杂度**：$O(n \log n)$。每个元素做一次二分（$\log n$）。
* **空间复杂度**：$O(n)$。开了长度为 `n` 的 `tails` 数组。

### 4. 递推过程图解
以 `nums = [10,9,2,5,3,7,101,18]` 为例：

```text
num    二分找第一个 >= num 的位置 left        tails(有效区)      size
10     空 → left=0=size，追加                  [10]              1
9      tails[0]=10>=9 → left=0 替换            [9]               1
2      tails[0]=9>=2  → left=0 替换            [2]               1
5      2<5 → left=1=size，追加                  [2,5]             2
3      第一个>=3 → left=1 替换 5                [2,3]             2
7      3<7 → left=2=size，追加                  [2,3,7]           3
101    7<101 → left=3=size，追加                [2,3,7,101]       4
18     第一个>=18 → left=3 替换 101             [2,3,7,18]        4
返回 size = 4
```

> 注意：`tails` 在替换后**不一定是真实的子序列**（如 `[2,3,7,18]` 中 18 并不真接在 7 后），但其**长度 `size` 始终等于 LIS 长度**——我们只关心长度，故成立。

---

## 💡 总结
最长上升子序列是**「以 i 结尾」型 DP** 的模板：状态必须锚定结尾元素才能判断「能否接龙」，转移是「在所有更小前驱里取 max + 1」，答案取 `max(dp)` 而非末位。

| 特性 | 解法一：动态规划 | 解法二：贪心 + 二分 |
| :--- | :--- | :--- |
| **思维出发点** | `dp[i]` = 以 nums[i] 结尾的 LIS，枚举更小前驱接龙 | `tails[k]` = 长度 k+1 的最小末尾，末尾越小越好接 |
| **代码表现** | 双重循环 `dp[i]=max(dp[i], dp[j]+1)`，初始化全 1，`res` 打擂台 | 二分 lower_bound 找第一个 `>= num`，替换或追加，`size` 即答案 |
| **时间** | $O(n^2)$ | $O(n \log n)$ |
| **空间** | $O(n)$ | $O(n)$ |

> ⚠️ 易错点：解法一① **状态要带「以 i 结尾」**；② **初始化全 1**；③ **答案是 `max(dp)`** 非 `dp[n-1]`；④ 严格递增用 `>`。解法二⑤ **二分是 lower_bound**（`tails[mid] < num` 才右移，相等不右移）；⑥ **`tails` 替换后不是真实子序列**，但 `size` 是正确长度。
